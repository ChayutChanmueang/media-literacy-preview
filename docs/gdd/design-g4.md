## 1. Overview (ภาพรวมของเกม)

เกม **G4 — แชร์ดีไหม?** เป็นเกมตอบคำถามฝึกทักษะ **การปกป้องความเป็นส่วนตัวออนไลน์ (Online Privacy)** โดยแสดงภาพจำลอง "สิ่งที่ผู้สูงอายุมักถ่ายและแชร์ลงโซเชียล/กลุ่ม LINE" ทีละข้อ แล้วให้ผู้เล่นตัดสินใจว่า **ควรแชร์หรือไม่** ก่อนกดส่งจริงในชีวิตประจำวัน

หัวใจของเกมคือการปลูกฝังแนวคิด **"แชร์ไปแล้วลบไม่ได้"** (digital footprint ถาวร) และฝึกให้ **หยุดคิดก่อนแชร์** — เชื่อมโยงกับสโลแกนโครงการ **"หยุด🛑 คิด🧠 ถาม💬 ทำ✅"** โดยตรง: ก่อนกดแชร์รูป/ข้อมูลใดๆ ให้ถามตัวเองว่า "ข้อมูลนี้ถ้าตกไปถึงมิจฉาชีพจะเกิดอะไรขึ้น?"

จุดต่างสำคัญจาก G1/G3 คือ **ตัวเลือกที่ 3 "ไม่แน่ใจ / ต้องเช็กก่อน"** ถูกออกแบบให้เป็น **คำตอบที่ได้รับคำชม** ไม่ใช่คำตอบผิด — เพราะในชีวิตจริง ทัศนคติที่ปลอดภัยที่สุดคือ "ถ้าไม่แน่ใจ อย่าเพิ่งแชร์" (ดู §6)

> ⚠️ **กติกาโครงการที่ยึดถือ:** ไม่มีการจับเวลา ไม่มีหน้าจอแพ้ (Game Over) ตอบพลาด = การ์ดเฉลยนุ่มนวลอธิบายผลกระทบ ไม่ใช่การลงโทษ ([Art Direction](./03-art-direction.md))

## 2. Core Gameplay Loop (วงลูปหลักการเล่น)

```mermaid
flowchart TD
    Start[เริ่มเกม] --> Show[แสดงการ์ดโจทย์ 1 ใบ: ภาพ + คำถาม \"แชร์ดีไหม?\"]
    Show --> Read[ผู้เล่นดูภาพ + ฟังเสียงอ่านโจทย์ ได้ไม่จำกัดเวลา]
    Read --> Choose{เลือก 1 ใน 3 ปุ่มใหญ่}

    Choose -- ✓ แชร์ได้ปลอดภัย --> Judge
    Choose -- ✗ ไม่ควรแชร์เด็ดขาด --> Judge
    Choose -- ❓ ไม่แน่ใจ/ต้องเช็กก่อน --> Cautious[การ์ดเฉลย: ชมเชยความรอบคอบ + เฉลยคำตอบที่ปลอดภัย + เกณฑ์วิเคราะห์]

    Judge{ตรงกับคำตอบปลอดภัยไหม?}
    Judge -- ตรง --> Correct[✓ เขียว + เสียงชื่นชม + การ์ดเฉลยเสริมเหตุผล]
    Judge -- ไม่ตรง --> Wrong[✗ ส้มอ่อน + การ์ดเฉลยอธิบายผลกระทบที่อาจตามมา]

    Cautious --> Disclose
    Correct --> Disclose
    Wrong --> Disclose
    Disclose{ภาพประกอบสร้างด้วย AI?}
    Disclose -- ใช่ --> Badge[แสดงป้าย ai_disclosure หลังเฉลย]
    Disclose -- ไม่ --> Next
    Badge --> Next{มีโจทย์ถัดไปไหม?}

    Next -- มี --> Show
    Next -- หมด --> Complete[หน้าสรุปเชิงบวก + ส่งดาวให้ GameShell ผ่าน onFinish]
```

## 3. Content Structure (โครงสร้างชุดโจทย์)

- คลังโจทย์เวอร์ชันแรก: **ภาพจำลอง 8 ข้อ** (ต้องแชร์ไม่ได้ ~5 ข้อ / แชร์ได้ปลอดภัย ~3 ข้อ) — เกินขั้นต่ำ AC (≥5) เพื่อให้สุ่มเล่นซ้ำได้
- **ไม่มีด่าน ไม่มีเลเวล** — เล่นรวดเดียวจบเหมือน G1/G3 (โจทย์สุ่มลำดับจากคลังเพื่อไม่จำเฉลย)
- โจทย์แต่ละข้อจับคู่กับ **ประเภทข้อมูลส่วนบุคคล (privacy category)** เพื่อให้ทีมวิชาการวิเคราะห์ได้ว่าผู้สูงอายุพลาดประเภทไหนบ่อย

| # | ภาพจำลอง (ตัวอย่าง) | คำตอบปลอดภัย | ประเภทข้อมูล | ผลกระทบถ้าหลุด |
|---|---------------------|--------------|--------------|-----------------|
| 1 | บัตรประชาชนถ่ายเต็มใบ (เลข 13 หลักครบ) | ❌ ไม่ควรแชร์ | national-id | ปลอมตัวตน เปิดบัญชี/สมัครสินเชื่อในชื่อเรา |
| 2 | รูปทะเบียนรถหน้าบ้านชัดเจน | ❌ ไม่ควรแชร์ | vehicle-plate | ตามหาที่อยู่ ปลอมป้ายทะเบียน |
| 3 | รูปหลานใส่ชุดนักเรียนหน้าป้ายโรงเรียน | ❌ ไม่ควรแชร์ | child-location | ระบุตัว/พิกัดเด็ก เสี่ยงต่อความปลอดภัย |
| 4 | เช็คอิน "อยู่บ้านคนเดียว ไปเที่ยว 5 วัน" ระบุพิกัดบ้าน | ❌ ไม่ควรแชร์ | home-location | บอกโจรว่าบ้านว่าง ช่วงเวลาที่ปลอดภัยจะงัด |
| 5 | สลิปโอนเงินโชว์เลขบัญชี/ชื่อเต็ม | ❌ ไม่ควรแชร์ | bank-account | นำเลขบัญชี+ชื่อไปใช้แอบอ้าง/หลอกโอน |
| 6 | รูปดอกไม้ในสวนหน้าบ้าน (ไม่มีข้อมูลระบุตัว) | ✅ แชร์ได้ปลอดภัย | none | ไม่มีข้อมูลส่วนบุคคลรั่วไหล |
| 7 | รูปอาหารร้านดัง (ไม่ติดหน้าคน/ป้ายทะเบียน) | ✅ แชร์ได้ปลอดภัย | none | ทั่วไป ไม่ระบุพิกัดบ้าน |
| 8 | ภาพคำคมให้กำลังใจ (ไม่มีข้อมูลตัวเอง) | ✅ แชร์ได้ปลอดภัย | none | เนื้อหาสาธารณะ แชร์ต่อได้ |

- ทุกการ์ดเฉลยกลุ่ม "ไม่ควรแชร์" ปิดท้ายด้วยช่องทางแจ้งเหตุ/ปรึกษา: **สายด่วน 1441 (ตำรวจไซเบอร์)** และ **1212 (ศูนย์ช่วยเหลือออนไลน์ ETDA)** สำหรับกรณีข้อมูลรั่วไหล
- โจทย์ต้องผ่านการตรวจจากทีมวิชาการ NAPLAB โดยเฉพาะเคส "แชร์ได้ปลอดภัย" ที่ต้อง **ไม่สอนให้ระแวงจนไม่กล้าแชร์อะไรเลย**

## 4. Content Data Design (คลังโจทย์แบบ data-driven)

โจทย์ทุกข้อเป็น data-driven (JSON ใน `src/data/`) เพื่อให้ทีมเนื้อหาเพิ่ม/แก้ได้โดยไม่แตะโค้ดเกม — แนวเดียวกับ `src/data/g8-raft-items.json`

### 4.1 โครงสร้างข้อมูลโจทย์ (`src/data/g4-privacy-items.json`)

```json
{
  "id": "g4-001",
  "image": "/images/g4/national-id.png",
  "image_alt": "ภาพบัตรประชาชนถ่ายเต็มใบเห็นเลข 13 หลัก",
  "prompt": "ลูกขอให้ส่งรูปบัตรประชาชนไปยืนยันตัวตนทางแชท — แชร์ดีไหม?",
  "safe_answer": "no_share",          // "safe_share" | "no_share"
  "category": "national-id",
  "explain": "บัตรประชาชนเต็มใบมีเลข 13 หลักที่มิจฉาชีพนำไปเปิดบัญชีหรือสมัครสินเชื่อในชื่อเราได้ หากจำเป็นต้องส่งจริง ให้ขีดคร่อมระบุวัตถุประสงค์และปิดข้อมูลที่ไม่จำเป็น",
  "impact_tags": ["ปลอมตัวตน", "สมัครสินเชื่อในชื่อเรา"],
  "ai_disclosure": true               // true เมื่อภาพประกอบสร้างด้วย AI → แสดงป้ายหลังหน้าเฉลย
}
```

- ฟิลด์ `safe_answer` มีเพียง 2 ค่า (`safe_share` / `no_share`) — ตัวเลือกที่ 3 **"ไม่แน่ใจ / ต้องเช็กก่อน" ไม่ใช่คำตอบผิดเสมอ** จึงไม่เก็บเป็น safe_answer แต่ให้ logic แสดงการ์ดชมเชย + เฉลยคำตอบที่ปลอดภัยแทน (ดู §6)
- `category` ใช้จัดกลุ่มวิเคราะห์เชิงวิชาการ (national-id / vehicle-plate / child-location / home-location / bank-account / none)
- ภาพประกอบทั้งหมดควรเป็นภาพจำลอง/วาดขึ้น (ไม่ใช้ภาพบุคคลจริง) — หากใช้ AI สร้างต้องตั้ง `ai_disclosure: true` และแสดงป้าย "⚠️ สื่อนี้สร้างโดย AI เพื่อการเรียนรู้" ตาม[นโยบาย AI Content](./00-concept.md#5-นโยบายการนำเสนอเนื้อหาที่สร้างจาก-ai-⚠️)

## 5. Screen Layout (การจัดหน้าจอ — Portrait เท่านั้น)

```
+---------------------------------------------------+
|  GameShell: progress dots ● ● ○ ○ ○   🔊 เสียงอ่าน | -> เชลล์กลาง (ไม่วาดเอง)
+---------------------------------------------------+
|                                                   |
|        +-------------------------------+          |
|        |                               |          |
|        |     [ ภาพจำลองสถานการณ์ ]      |          | -> การ์ดภาพใหญ่ ≥ 60vw
|        |                               |          |
|        +-------------------------------+          |
|                                                   |
|   "ลูกขอให้ส่งรูปบัตรประชาชน... แชร์ดีไหม?"          | -> คำถาม ฟอนต์ ≥ 22px
|                                                   |
|   +-------------------------------------------+   |
|   |  ✓  แชร์ได้ปลอดภัย                        |   | -> ปุ่มเขียว ≥ 56px
|   +-------------------------------------------+   |
|   |  ✗  ไม่ควรแชร์เด็ดขาด                     |   | -> ปุ่มแดง/ส้ม ≥ 56px
|   +-------------------------------------------+   |
|   |  ❓  ไม่แน่ใจ / ต้องเช็กก่อน               |   | -> ปุ่มเหลือง ≥ 56px
|   +-------------------------------------------+   |
+---------------------------------------------------+
```

- **การ์ดภาพ:** ใหญ่ชัด รองรับแตะเพื่อ **ซูม** (ยืมแนวทางจาก G3 ที่มี ZoomIn/ZoomOut) เพราะรายละเอียดข้อมูลส่วนตัวในภาพ (เลขบัตร/ทะเบียน) ต้องมองเห็นชัด
- **ปุ่ม 3 ตัวเลือกแนวตั้ง:** สูง ≥ 56px, มีทั้ง **ไอคอน + สี + ข้อความ** (ไม่พึ่งสีเดี่ยว) — ✓ เขียว / ✗ ส้ม / ❓ เหลือง
- **หน้าเฉลย (Feedback Card):** เปิดทับหลังเลือกตอบ แสดงไอคอนถูก/ผิด, คำอธิบายผลกระทบ (`explain`), แท็กผลกระทบ (`impact_tags`), ช่องทางแจ้งเหตุ 1441/1212 และปุ่มใหญ่ "ข้อต่อไป →"
- ทุกข้อความ ≥ 20px, ปุ่ม ≥ 22px, Contrast ≥ 4.5:1, Touch target ≥ 48×48px ตาม [Art Direction](./03-art-direction.md)

## 6. Answer Logic & Positive Reinforcement (ตรรกะคำตอบ + การเสริมแรงเชิงบวก)

| ผู้เล่นเลือก | ผลลัพธ์ | หน้าเฉลย |
|-------------|---------|----------|
| ตรงกับ `safe_answer` | ✓ ถูก + เสียงชื่นชม | ยืนยันคำตอบ + เสริมเหตุผลว่าทำไมปลอดภัย/ไม่ปลอดภัย |
| ไม่ตรงกับ `safe_answer` | ✗ (ส้มอ่อน ไม่ใช่แดงจัด/เสียงตกใจ) | อธิบายผลกระทบที่อาจตามมาอย่างเป็นมิตร ("ถ้ารูปนี้ตกไปถึงมิจฉาชีพ อาจ...") |
| ❓ ไม่แน่ใจ / ต้องเช็กก่อน | 💛 **ได้รับคำชม** (นับเป็น "รอบคอบ" ไม่ใช่ผิด) | ชมเชยความระมัดระวัง ("รอบคอบมากค่ะ ถ้าไม่แน่ใจ อย่าเพิ่งแชร์คือคำตอบที่ปลอดภัยที่สุด") แล้วเฉลยคำตอบปลอดภัย + เกณฑ์วิเคราะห์ 3 ข้อ (มีข้อมูลระบุตัวตนไหม / บอกพิกัดบ้านไหม / ถ้าหลุดแล้วเสียหายไหม) |

- **การนับดาว (เบื้องหลัง):** คำนวณจากสัดส่วนการตอบ "ปลอดภัย" (เลือกตรง `safe_answer` **หรือ** เลือก "ไม่แน่ใจ" ในข้อที่คำตอบคือ `no_share` — ถือว่าปลอดภัยเชิงพฤติกรรม) — ≥80% = 3 ดาว, ≥50% = 2 ดาว, ต่ำกว่า = 1 ดาว (ขั้นต่ำ 1 ดาวเสมอ)
- หน้าสรุปโชว์เฉพาะ **ดาว + คำชม** ไม่โชว์เปอร์เซ็นต์หรือจำนวนข้อที่พลาด
- **จบเสมอ = ผ่านเสมอ** ไม่มีเงื่อนไขแพ้ (สอดคล้อง Win/Lose ของโครงการ)

## 7. Art Direction & Motion (ทิศทางภาพและการเคลื่อนไหว)

- โทนภาพสว่างสบายตา ใช้ token หลักโครงการ (teal `--primary`) — การ์ดภาพขอบโค้ง เงานุ่ม
- การเปลี่ยนข้อ: fade/slide เบาๆ ~300ms | หน้าเฉลย: slide-up นุ่มนวล | ไม่มีเอฟเฟกต์กะพริบถี่
- `prefers-reduced-motion`: เปลี่ยน transition ทั้งหมดเป็น fade ทันที ไม่มีการเลื่อน
- ✓ เขียว / ✗ ส้มอ่อน / ❓ เหลือง — ทุกจุดมีไอคอนกำกับ ไม่พึ่งสีอย่างเดียว

## 8. Technical Implementation Details (สเปกทางเทคนิค)

### Component & Integration
- Component: **`G4ShareOrNot`** วางใน `src/components/` ตามแบบแผน G-number เดิม — คุยกับ `GameShell` ผ่าน props มาตรฐาน `onFinish(stars)` + `logEvent` ไม่สร้าง layout/progress dots เอง
- เขียนเป็น **`.tsx`** ตั้งแต่ต้น (พัฒนาหลัง migration Next.js + TypeScript — แนวเดียวกับ `G8RaftCrossing.tsx`)
- React state ล้วน + CSS transitions สำหรับ fade/slide — ไม่ต้องใช้ physics/timer ใดๆ
- คลังโจทย์: `src/data/g4-privacy-items.json` (อนาคตอาจย้ายเข้า Supabase ร่วมกับ US-MIGRATE-03)
- รองรับปุ่มเสียงอ่านโจทย์+เฉลย (TTS/เสียงอัด ตาม Open Decision โครงการ) — reuse กลไก Volume2/VolumeX แบบ G1/G3
- **ลงทะเบียนใน Dev Game Hub** (`src/app/dev/games/page.tsx`): เปลี่ยน entry G4 จาก `component: null` เป็น `G4ShareOrNot` และ `status: "planned"` → `"qa"` เมื่อพัฒนาเสร็จ

```javascript
logEvent('game_start',   { game_id: 'g4' });
logEvent('answer',       { game_id: 'g4', item_id: 'g4-001', choice: 'no_share', correct: true });

logEvent('feedback_view',{ game_id: 'g4', item_id: 'g4-001', category: 'national-id' });
logEvent('toggle_audio', { game_id: 'g4', item_id: 'g4-001', action: 'play' });
logEvent('game_complete',{ game_id: 'g4', stars: 3, total_items: 8 });
```

ข้อมูล `answer` แยกตาม `item_id` + `category` มีค่าต่อทีมวิชาการ — ใช้วิเคราะห์ว่าประเภทข้อมูลส่วนตัวแบบไหนที่ผู้สูงอายุเผลอคิดว่า "แชร์ได้" บ่อยที่สุด เพื่อเน้นเนื้อหาอบรม

## 9. Open Questions (คำถามเปิดรอทีมตัดสินใจ)

1. **ลำดับความสำคัญ / Sprint:** ปัจจุบันเป็น Nice (Topic 1) วางไว้ Sprint 06 — ยืนยันว่าไม่เร่งก่อนงานเชียงใหม่ 6–7 ส.ค.
2. **ที่มาของภาพประกอบ:** วาด/สังเคราะห์เอง หรือใช้ AI สร้าง? (กระทบการตั้ง `ai_disclosure`) — ต้องไม่ใช้ภาพบัตร/บุคคลจริงเด็ดขาด
3. **คลังโจทย์:** ต้องการทีมวิชาการ NAPLAB ช่วยเขียน/ตรวจ 8 ข้อ โดยเฉพาะเคส "แชร์ได้ปลอดภัย" ที่ต้องไม่สอนให้ระแวงเกินเหตุ
4. **การซูมภาพ:** จำเป็นทุกข้อ หรือเฉพาะข้อที่มีรายละเอียดเล็ก (เลขบัตร/ทะเบียน)? — playtest กับผู้สูงอายุจริงก่อนสรุป
