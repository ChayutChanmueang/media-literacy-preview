# G17 — โล่กันโกง (Scam Breaker)

> สถานะ: 🔍 In QA — เปิดในโหมดอิสระ หมวด "เกมเพื่อการเรียนรู้" (lesson id `g17`) + Dev Game Hub (`/dev/games`) — ไม่อยู่ในโหมดเนื้อเรื่อง/โหมดวิจัย (เดิมคือ prototype GP6)
> โค้ด: `src/components/G17ScamBreaker.tsx` | ผังด่าน: `src/data/g17-levels.json` | ภาพ: ใช้ pool ภาพของ G3 (`src/data/g3-questions.json`)
> ต้นแบบ: ไฟล์ HTML `ballbounce.html` ของทีม (เกมเด้งลูกทำลายบล็อกแบบ Breakout)

## เป้าหมาย

เกมแอคชันเบา ๆ — แต่ละด่านบล็อกทั้งกริดต่อกันเป็น **ภาพ 1 ภาพจากคลังภาพของ G3** (ภาพ AI / ภาพตัดต่อ / ภาพถ่ายจริง) ผู้เล่นเด้งโล่ทำลายบล็อกจนหมด แล้วหน้าจบด่านเฉลยว่าภาพนั้นเป็นภาพแบบไหน พร้อมคำอธิบายชุดเดียวกับ G3 — เน้นเล่นสนุกและได้ดูภาพซ้ำอีกครั้ง มากกว่าวัดความเร็วมือ

> เดิม (ถึง 0.15.0) บล็อกพิมพ์ข้อความมิจฉาชีพ (โอนเงินด่วน, พัสดุตกค้าง …) และหน้าจบด่านอธิบายทีละข้อความ — เปลี่ยนเป็นบล็อกภาพตามคำขอทีม ข้อความชุดเดิมดูได้จากประวัติ git ของ `src/data/g17-scam-phrases.json`

## Flow

1. `GameIntro` — "โล่กันโกง" + รายการของช่วย 🪄 🍄 🐢
2. เล่น 3 ด่าน — บล็อกวางบนกริด 10 × 6 ช่องตามผังใน JSON (ดูหัวข้อ "ผังด่าน / การวางบล็อก")
   - ตัวรับด้านล่างเป็นแถบสีเขียวเข้มเขียน **🚨 191 👮** (เบอร์ตำรวจ) — ลากตรงไหนของจอก็ได้ แถบตามนิ้ว (เดสก์ท็อป: ตามเมาส์)
   - "ลูก" ที่เด้งเป็นโล่ 🛡️ รออยู่บนแถบ 191 มีป้าย "แตะจอเพื่อปล่อยโล่" — แตะ (ไม่ลาก) = ปล่อย (ข้อความในเกม เช่น ของช่วย ใช้คำว่า "โล่" แทน "ลูกบอล" ทั้งหมด)
   - มุมเด้งขึ้นกับตำแหน่งที่โล่กระทบแถบ 191 (สูงสุด 60°) — ทุกครั้งที่เด้งจากแถบ ความเร็วเพิ่ม 2% (ครั้งเดียวไม่รู้สึก แต่ค่อย ๆ เร็วขึ้น) สูงสุด 1.5 เท่าของความเร็วเริ่มต้น (~20 ครั้ง) — เด้งกล่อง/ขอบจอไม่นับ รีเซ็ตส่วนที่เร่งจากการเด้งเมื่อโล่หลุด
   - บล็อกแตกมีโอกาส 25% ดรอปของช่วย: 🪄 แยกเป็น 3 อัน (สูงสุด 6 อัน) · 🍄 โล่ใหญ่ขึ้น · 🐢 ลดความเร็ว **25% จากความเร็วตอนนั้น** (รวมที่เร่งจากการเด้งแล้ว) เก็บหลายตัวลดซ้อนได้ แต่ไม่ต่ำกว่าครึ่งหนึ่งของความเร็วเริ่มต้น หลังจากนั้นการเด้งยังเร่งต่อจากความเร็วใหม่ (มีผลถึงจบด่าน)
   - ลูกหลุดหมด → ขึ้นข้อความ "ไม่เป็นไร ลองใหม่อีกครั้งนะ" แล้ววางลูกใหม่บนโล่ **ไม่มีแพ้**
   - แถบบน: "ด่าน n / 3" และ "เหลือ n กล่อง" (นับทุกกล่องที่ทำลายได้)
3. จบด่าน → หน้า "ผ่านด่านที่ n แล้ว!" แสดง **ภาพเต็มของด่านนั้น** + เฉลยแบบมีไอคอนกำกับ (🤖 ภาพนี้สร้างด้วย AI · ✂️ ภาพนี้เป็นภาพตัดต่อ · 📷 ภาพนี้เป็นภาพถ่ายจริง) + `claim` + `explanation` + `aiDisclosure` (ถ้ามี) จาก G3 (เลื่อนอ่านได้) → ปุ่ม "ไปด่านต่อไป" / "จบเกม"
4. จบด่าน 3 → `onFinish(stars)`

## ผังด่าน / การวางบล็อก

พื้นที่บล็อกเป็นกริด 10 คอลัมน์ × 6 แถว (ช่องกว้าง = ความกว้างจอ ÷ 10, สูง 44px) ผังแต่ละด่านเก็บเป็นสตริงใน `levels[].grid` ของ `g17-scam-phrases.json`:

- `o` = ช่องสำหรับวางบล็อก (ทำลายได้)
- ตัวอักษรอื่น = ช่องว่าง (ไม่มีบล็อก)
- **ไม่มีกำแพงทึบทำลายไม่ได้แล้ว** (เอาออกจากเกม) — ช่องที่เคยเป็นกำแพง `#` ในด่าน 2–3 เปลี่ยนเป็นบล็อกทำลายได้ (`o`) ภาพจึงยังเต็มกริด

```
ด่าน 1–3 (ผังเดียวกัน)
oooooooooo
oooooooooo
oooooooooo
oooooooooo
oooooooooo
oooooooooo
```

**การวางในแต่ละด่าน:** ทุกช่อง `o` มีบล็อกเปล่า (ไม่มีข้อความ) **ขนาด 1×1 ช่อง ช่องละ 1 ก้อน** ทุกด่าน — กริดเต็ม 10×6 จึงมี 60 ก้อนต่อด่าน รอยตัดของภาพเป็นตารางเท่ากันทุกครั้ง

**ผ่านด่านเมื่อทำลายบล็อกครบทุกก้อน** แถบบนแสดง "เหลือ n กล่อง" บล็อกแตกแล้วดรอปของช่วยได้

แก้ผังได้ที่ JSON โดยตรง (ทุกแถวต้องยาวเท่ากัน)

## ภาพประจำด่าน (จากคลัง G3)

- ตอนเริ่มเกม สุ่มภาพจาก pool ของ G3 (`g3-questions.json` → `pool`, ตอนนี้ 27 ภาพ ทุกหมวดปนกัน) มา **ด่านละ 1 ภาพ ไม่ซ้ำกันในเกมเดียว** และโหลดภาพทั้ง 3 ด่านไว้ล่วงหน้าทันที
- ภาพถูกย่อให้ **เต็มพื้นที่กริดทั้งหมด** (เหมือน `object-fit: cover` จัดกึ่งกลาง — ภาพแนวตั้งจะถูกตัดบน-ล่างออกบ้าง) แล้วแต่ละบล็อกวาดเฉพาะส่วนของภาพที่อยู่ใต้ตัวเอง ณ ตำแหน่งเดิม — เรียงต่อกันแล้วเห็นเป็นภาพเดียว มีขอบขาวบาง ๆ คั่นให้ยังเห็นเป็นก้อน (บล็อกเป็นมุมฉากเหลี่ยม ไม่มน และวางชิดกันไม่มีช่องว่าง — `BRICK_INSET = 0`)
- ถ้าภาพยังโหลดไม่เสร็จ บล็อกจะเป็นสีเทาเปล่าก่อน แล้วภาพขึ้นเองเมื่อโหลดเสร็จ (เล่นได้ตลอด)
- หน้าจบด่านแสดงภาพเต็ม (`object-contain`) — ภาพ AI/ตัดต่อแสดง `aiDisclosure` ตามนโยบาย AI disclosure เสมอ
- เพิ่ม/แก้ภาพ = แก้ที่ pool ของ G3 ที่เดียว G17 ใช้ตามอัตโนมัติ

## การให้คะแนน / ดาว

นับจำนวนครั้งที่ลูกหลุดหมดทั้งเกม: ≤ 3 = 3 ดาว, ≤ 8 = 2 ดาว, มากกว่านั้น = 1 ดาว (เล่นจบได้เสมอ) — เผื่อไว้กว้างเพราะด่านเต็มกริดใช้เวลานานขึ้น

`game_intro_start`, `enter_level {level, bricks, picture_id}`, `brick_break {bricks_left}`, `item_collect {item, speed_multiplier}`, `ball_miss {level, misses}`, `level_complete {level, picture_id, misses}`, `game_complete {levels, misses, pictures, stars}`, `g17_dev_skip_level {level}` (ปุ่ม "ข้ามด่าน" แสดงเฉพาะตอน `npm run dev` สำหรับ QA)

## เรื่องที่ยังเปิดอยู่

- ทุกด่านมีบล็อก 60 ก้อน (1×1 เต็มกริด) และต้องทำลายทั้งหมด — ถ้ายาวไป ลดแถว `o` หรือเปลี่ยนบางช่องเป็นช่องว่างใน JSON
- กริดเป็นแนวนอน (~10:6) ภาพแนวตั้งบางภาพจะเห็นแค่ช่วงกลางระหว่างเล่น (หน้าจบด่านเห็นเต็มภาพ) — ถ้าต้องการให้เห็นครบ ต้องเลือกภาพแนวนอน/ครอปภาพไว้สำหรับ G17
- ภาพชุดใหม่ของ G3 บางไฟล์ใหญ่ 2–3 MB — บนเน็ตช้าบล็อกอาจเป็นสีเทาสักพักก่อนภาพขึ้น ควรย่อ/บีบอัดภาพก่อนใช้จริง
- ยังไม่มีการถามผู้เล่นว่าภาพจริงหรือ AI ก่อนเฉลย (เป็นแค่การเฉลยให้ดู) — ถ้าจะผูกกับบทเรียน G3 อาจเพิ่มให้ทายก่อน
- ยังไม่ได้ทดสอบกับผู้สูงอายุจริง — ความเร็วเริ่มต้น (38% ของความสูงพื้นที่เล่นต่อวินาที, 200–340 px/s), การเร่ง (+2% ต่อการเด้ง, เพดาน 1.5 เท่า) และขนาดแถบ 191 (34% ของความกว้าง) อาจต้องปรับ
- ป้าย AI/จริงและคำอธิบายของภาพมาจาก G3 ซึ่งยังรอทีมวิชาการยืนยัน (ดู `public/assets/g3-images/README.md`)
- โล่ (ลูกที่เด้ง)/ของช่วยยังเป็น emoji — ถ้าจะใช้ภาพจริงให้ทำตาม art direction
- ไม่มี `prefers-reduced-motion` แบบเฉพาะ เพราะตัวเกมคือการเคลื่อนไหว — ถ้าเข้า lesson flow ต้องตัดสินใจว่าจะมีทางเลือกอื่นให้ผู้ที่ไม่สะดวกเล่นเกมแอคชันหรือไม่
