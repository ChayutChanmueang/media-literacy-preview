# G19 — เรียงผลไม้ (Fruit Match / match-3)

> สถานะ: 🔍 In QA — เปิดในโหมดอิสระ หมวด "เกมสนุก" (lesson id `g19`) + Dev Game Hub (`/dev/games`) — ไม่อยู่ในโหมดเนื้อเรื่อง/โหมดวิจัย (เดิมคือ prototype GP8)
> โค้ด: `src/components/G19FruitMatch.tsx`
> ต้นแบบ: ไฟล์ HTML `candy crush4.HTML` ของทีม (เกมเรียงผลไม้แนว Candy Crush)

## เป้าหมาย

เกมเรียงของ 3 ชิ้น (match-3) เพื่อความสนุกล้วน ๆ — **ไม่มีเนื้อหาบทเรียน**

## Flow

1. `GameIntro` — "เรียงผลไม้" + วิธีเล่น (แทนหน้าเริ่มเกมของต้นแบบ)
2. กระดาน 5×5 ผลไม้ 5 ชนิด (🍎 🍉 🍇 🍌 🍊) — บล็อกขาวมนวางบน**แผงกระดานใหญ่ 1 แผง** (เขียวกลาง มุมมน เงาด้านใน) บนพื้นเขียวอ่อน — ข้อความบอกสถานะ/คำใบ้**ใต้กระดาน**เป็น**ตัวหนังสือล้วน ไม่มีกล่องพื้นหลัง** (สีตัวอักษรบอกโทน) ขนาด 20px **บรรทัดเดียวเสมอ** ทุกข้อความสั้นพอให้พอดีจอกว้าง 320px (ค่าเริ่ม: "ลากหรือแตะ 2 ช่องที่ติดกันเพื่อสลับ") หัวจอคะแนนซ้าย / จำนวนครั้งที่สลับได้ขวา หน้าตาเดียวกับต้นแบบ — ได้คะแนนแล้วมีตัวเลข **"+ 30"** สีเขียวขึ้นต่อท้ายคะแนน (เช่น "100 + 30") ค้าง 0.4 วิ แล้วคะแนนวิ่งขึ้น / "+ 30" วิ่งลงพร้อมกัน 0.7 วิ ใกล้หมดแล้ว "+ N" ตกลงและจางหาย (ถ้าเรียงต่อระหว่างนับ ตัวเลข "+ N" จะรวมเพิ่ม; เปิด reduced motion เช่นปิด "Animation effects" ของ Windows → ยังมี "+ N" และนับเหมือนเดิม แต่จางเข้า/ออกเฉย ๆ ไม่เด้ง/ไม่ตกลง)
   - **ลาก** ผลไม้ไปทางช่องข้าง ๆ (≥ 20px) เพื่อสลับ — เหมือนต้นแบบ
   - **แตะ** ผลไม้ 1 ช่อง (มีกรอบน้ำเงิน + ข้อความ "เลือก🍉แล้ว แตะช่องข้าง ๆ") แล้วแตะช่องที่ติดกันเพื่อสลับ, แตะช่องเดิมซ้ำ = ยกเลิก, แตะช่องที่ไม่ติดกัน = เปลี่ยนตัวที่เลือก
   - สลับแล้วเรียงได้ 3 ผลขึ้นไป (แนวนอน/แนวตั้ง) → ผลไม้หายไป ได้ **10 คะแนนต่อผล** ผลไม้ด้านบนตกลงมา ผลใหม่หล่นจากด้านบน ถ้าเรียงต่อได้อีกจะได้คะแนนซ้ำ ("🎉 ต่อกันอีก! ×2")
   - สลับแล้วไม่เรียง → สลับกลับเหมือนต้นแบบ + "ยังไม่ครบ 3 ผล ลองคู่อื่นนะ" **ไม่เสียครั้ง**
   - **บทสอนตอนเข้าเกมครั้งแรก** (รอบแรกหลังเปิดเกม): มือสาธิตโผล่ 0.5 วิหลังกระดานขึ้น (แถบสถานะยังเป็นวิธีเล่น) และ**ค้างอยู่จนกว่าจะเรียงได้ครั้งแรก** — แตะผลไม้ / สลับผิด ("ยังไม่ครบ 3 ผล ลองลากตามมือดูนะ") / ปล่อยไว้นาน มือก็ไม่หาย เรียงได้ (คู่ไหนก็ได้ ไม่จำเป็นต้องตามมือ) → มือหาย จบบทสอน
   - **คำใบ้** (หลังบทสอน และรอบ "เล่นอีกครั้ง"): มือแบบเดียวกันโผล่ตอนเริ่มรอบ และทุกครั้งที่ไม่ได้ขยับ 7 วิ (กรอบประกะพริบที่คู่ที่สลับได้ + "💡 ลองสลับ 2 ช่องที่กะพริบดูสิ"): **มือ 👆 สีเหลือง** วนรอบละ 2.4 วิ — โผล่ (ท่าปล่อย: ยกขึ้น ใหญ่ขึ้นนิดหน่อย) บนผลไม้ที่ควรลาก → กดลง (ท่ากด: ต่ำลง เล็กลงนิดหน่อย + วงกลมสีเหลืองอำพันที่ปลายนิ้ว) → เลื่อนไปช่องข้าง ๆ ที่ต้องสลับ → ปล่อย (ยกขึ้น วงกลมจาง) → จางหาย — เลือกลากผลที่ย้ายแล้วเรียงได้จริง คำใบ้หายไปเมื่อแตะ/ลากกระดาน ไม่ต้องทำตาม **เล่นแม้เปิด reduced motion** (เป็นตัวคำแนะนำเอง ขยับช้าและเล็ก)
   - หลังเรียงแล้ว **ไม่มีคู่ไหนสลับได้อีก → จบรอบทันที** (แม้ยังเหลือครั้งให้สลับ): แถบสถานะ "ไม่มีคู่ให้สลับแล้ว มาดูคะแนนกัน" + ข้อความชมกลางกระดาน "เก่งมาก! 🎉 / ไม่มีคู่ให้สลับแล้ว" → หน้าคะแนนเหมือนจบปกติ (ไม่ใช่หน้าแพ้) — กระดานเริ่มต้นการันตีว่ามีคู่ให้สลับเสมอ
   - ระบบ**สับกระดานใหม่อัตโนมัติ**แบบเดิม ("ไม่มีคู่ให้สลับ สับผลไม้ใหม่ให้นะ" แล้วสุ่มกระดานใหม่ ไม่เสียครั้ง) **ยังเก็บไว้ในโค้ด** — สลับกลับได้ที่ค่า `RULES.onNoMoves` (`"end"` = จบรอบ ใช้อยู่ / `"reshuffle"` = สับใหม่) เผื่อดีไซน์เปลี่ยนกลับ
3. สลับสำเร็จครบ **20 ครั้ง** → แถบสถานะ "ครบ 20 ครั้งแล้ว มาดูคะแนนกัน" + **ข้อความชมลอยขึ้นกลางกระดาน** "เก่งมาก! 🎉 / เล่นครบ 20 ครั้งแล้ว" (ตัวหนังสืออย่างเดียว ไม่มีกล่องพื้นหลัง — ตัวขาวขอบน้ำตาลเข้มให้อ่านออกบนผลไม้ — จางเข้า+ขยายขึ้น 0.5 วิ ค้าง 1.8 วิ จางออก 0.45 วิ) → หน้าคะแนน "เก่งมาก! ได้คะแนน N คะแนน" + "สถิติดีที่สุด" / "🎉 สถิติใหม่ของคุณ!" ตั้งแต่รอบที่ 2 → ปุ่ม "เล่นอีกครั้ง" / "จบเกม" → `onFinish(stars)`

กระดานเริ่มต้นและกระดานที่สับใหม่ไม่มีแถวที่เรียงอยู่แล้ว และมีคู่ที่สลับได้อย่างน้อย 1 คู่เสมอ

## ด่านประจำวัน (seed ตามวันที่)

เพื่อความยุติธรรม ด่านสุ่มด้วย seed = **วันที่ของวันนั้น** (`YYYY-MM-DD` ตามเวลาไทย `Asia/Bangkok` — มือถือที่ตั้ง timezone ผิดก็ได้ด่านเดียวกัน) แทน `Math.random` → **ทุกคนได้ด่านเดียวกันทั้งวัน** เปลี่ยนด่านใหม่ตอนเที่ยงคืนเวลาไทย

- PRNG: mulberry32 (seed จาก hash FNV-1a ของ `G19:<วันที่>:<ชื่อชุด>`)
- แยกชุดตัวเลขสุ่มเป็น 3 แบบ เพื่อไม่ให้ลำดับการเล่นของแต่ละคนทำให้ผลไม้ที่ได้ต่างกัน:
  - `board` — กระดานเริ่มต้น
  - `column-0` … `column-4` — ผลไม้ที่หล่นเติม **แยกรายคอลัมน์**: ผลไม้ลูกที่ n ที่หล่นลงคอลัมน์ไหนก็ตาม เหมือนกันทุกคน ไม่ว่าจะเคลียร์ตรงไหนก่อน
  - `shuffle` — กระดานที่สับใหม่ตอนไม่มีคู่ให้สลับ (ครั้งที่ n ของวันเหมือนกันทุกคน)
- "เล่นอีกครั้ง" ในวันเดียวกัน = เล่นด่านเดิมซ้ำ (seed ล็อกตอนเริ่มรอบ เล่นข้ามเที่ยงคืนก็ยังเป็นด่านเดิมจนจบรอบ)
- คำใบ้เมื่อไม่ได้ขยับยังสุ่มด้วย `Math.random` ได้ เพราะแค่เลือกว่าจะชี้คู่ไหน ไม่ได้เปลี่ยนกระดาน
- ผู้เล่นที่สลับเหมือนกันทุกครั้งจะได้กระดานเหมือนกันทุกขั้น; ถ้าสลับต่างกัน กระดานก็ต่างกันได้ แต่ "คิว" ผลไม้ของแต่ละคอลัมน์ยังเหมือนกัน

## คะแนน / ดาว

- คะแนนของรอบ = 10 × จำนวนผลไม้ที่หายไปทั้งหมด (รวมที่หล่นแล้วเรียงต่อเอง)
- สถิติดีที่สุดเก็บไว้ระหว่างเปิดเกมอยู่เท่านั้น
- ดาวคิดจากสถิติดีที่สุดตอนกด "จบเกม": ≥ 900 = 3 ดาว, ≥ 500 = 2 ดาว, น้อยกว่านั้น = 1 ดาว

## ส่วนที่เปลี่ยนจากต้นแบบ HTML (ตามกติกา AGENT.md)

| ต้นแบบ HTML | G19 | เหตุผล |
|---|---|---|
| จับเวลา 60 วินาที | สลับได้ 20 ครั้ง ไม่จับเวลา | ห้ามจับเวลากดดัน |
| หน้า "จบเกม" สีแดง | หน้าคะแนนเชิงบวก + สถิติดีที่สุด + เล่นอีกครั้ง/จบเกม | ห้ามหน้าจอแพ้ |
| หน้าเริ่มเกมแบบ overlay | `GameIntro` ร่วมของโปรเจกต์ | ให้เหมือนเกมอื่น |
| ลากสลับอย่างเดียว | ลาก หรือแตะ 2 ช่อง | ผู้สูงอายุบางคนลากไม่ถนัด |
| ไม่มีคำแนะนำ | แถบข้อความบอกสถานะ + คำใบ้เมื่อไม่ได้ขยับ 7 วิ | ไม่ทิ้งให้งงว่าต้องทำอะไร |
| กระดานอาจตันจนไม่มีคู่ให้สลับ | จบรอบด้วยหน้าคะแนนเชิงบวก (โค้ดสับกระดานใหม่อัตโนมัติยังเก็บไว้ สลับได้ที่ `RULES.onNoMoves`) | กันเล่นต่อไม่ได้ / ค้าง |
| ตัวเลขสีส้ม `#e98824` | สีส้มเข้ม `#B45309` | contrast ≥ 4.5:1 |

คงไว้เหมือนต้นแบบ: ขนาดกระดาน 5×5, ผลไม้ 5 ชนิด, พื้นหลัง/หัวจอ/บล็อกขาว, เวลาสลับ/สลับกลับ 300 ms, การให้คะแนน 10 ต่อผล

Animation ที่ช้าลงจากต้นแบบ (ต้นแบบเร็วเกินจนมองไม่ทัน):
- ผลไม้ที่เรียงได้ **ย่อหายไป** 450 ms (ต้นแบบ 200 ms) — พองขึ้นเล็กน้อยก่อนแล้วย่อลงจนหาย จางหายเฉพาะช่วงท้าย
- ผลไม้ **หล่นลง** แทนที่ช่องว่าง 600 ms (ต้นแบบ 300 ms)

ผลไม้เป็นอีโมจิที่รูปร่างต่างกัน จึงไม่ได้แยกด้วยสีอย่างเดียว
