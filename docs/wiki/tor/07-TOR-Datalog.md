# รายการข้อมูลที่ต้องจัดเก็บฝั่ง Backend ตาม TOR

## งานจ้างเหมาพัฒนาเว็บแอปพลิเคชันเชิงโต้ตอบ (Interactive Web Application) พร้อมเกมประกอบสื่อการเรียนรู้รู้เท่าทันสื่อ สำหรับผู้สูงอายุ

> **ที่มาของเอกสาร:** สรุปจาก **[04-TOR_MOU_Masscom_CAMT.md](./04-TOR_MOU_Masscom_CAMT.md)** (ถอดความจาก `04-MOU โครงการวิจัย Masscom ร่วม CAMT.pdf`) โดยดึงเฉพาะข้อกำหนดที่เกี่ยวกับการจัดเก็บข้อมูล รหัสอ้างอิงใช้รูปแบบ `MOU 3.x.x (ลำดับ)` ชุดเดียวกับ [เทมเพลตงวดที่ 1](./05-TOR-งวดที่%201.md) และ [เทมเพลตงวดที่ 2](./06-TOR-งวดที่%202.md)

## 1. เป้าหมายของการจัดเก็บข้อมูล

- **ติดตามและประเมินผลโครงการวิจัย:** วัดระดับทักษะการรู้เท่าทันดิจิทัลของผู้สูงอายุและผู้ถ่ายทอดความรู้ (MOU 2.3, 3.4)
- **เชื่อมโยงกับแบบประเมิน:** ข้อมูลต้องเชื่อมโยงหรือส่งออกได้ เพื่อใช้ประกอบแบบประเมินก่อน-หลังการอบรม (Pre/Post Assessment) (MOU 2.3, 3.4)
- **ส่งมอบในงวดที่ 2:** ต้องส่งมอบข้อมูลสำหรับการประเมินผล เพื่อใช้ในระยะที่ 3-4 ของแผนงานวิจัย ได้แก่ การนำองค์ความรู้สู่ผู้สูงอายุ และการติดตามประเมินผล ในเดือนที่ 6-12 (MOU 10.1.2)

## 2. รายการข้อมูลที่ต้องจัดเก็บ

| # | ข้อมูลที่เก็บ | รายละเอียด | เหตุผลที่ต้องเก็บ | อ้างอิง |
|---|---|---|---|---|
| 1 | **Anonymous session ID** | สร้างโดยไม่มี login เก็บแบบ Hybrid Persistence (localStorage + Cookie, Max-Age 1 ปี, SameSite=Lax) และ sync ระหว่างสองที่อัตโนมัติ | ใช้ผูกข้อมูลทุกอย่างของผู้ใช้คนเดียวกันโดยไม่ระบุตัวตน ป้องกันข้อมูลหายเมื่อ In-App WebView (เช่น LINE) ล้างแคช และใช้เป็นเงื่อนไข RLS ให้แต่ละ session เขียนได้เฉพาะข้อมูลของตัวเอง | MOU 3.1.3 (1), 3.1.3 (7), 3.1.4 (3), 3.1.6 (5) |
| 2 | **ช่วงอายุ** | ผู้ใช้เลือกจากปุ่มในหน้าขอความยินยอม เก็บเป็นช่วง ไม่ใช่วันเกิด | ใช้แยกผลการเรียนตามช่วงอายุ และดูว่าเข้าถึงกลุ่มเป้าหมายผู้สูงอายุได้จริงหรือไม่ เก็บเป็นช่วงตามหลัก Data Minimization | MOU 2.3, 3.1.3 (1), 3.1.6 (4) |
| 3 | **ตำแหน่งแบบหยาบ** (จังหวัด/อำเภอ/ตำบล) | แปลงจาก IP ที่ชั้น edge ก่อนถึงแอปพลิเคชัน ใช้เป็นค่าตั้งต้น แล้วให้ผู้ใช้ยืนยันหรือแก้ไขเอง | ใช้วัดผลการเผยแพร่สื่อในพื้นที่วิจัย 3 จังหวัดนำร่อง (เชียงใหม่ แพร่ น่าน) และนับจำนวนผู้เรียนแยกตามพื้นที่ | MOU 3.1.2, 3.1.3 (1), 3.1.3 (7), 3.1.6 (3) |
| 4 | **สถานะความยินยอม** (ยินยอม/ไม่ยินยอม) | บันทึกผลจากหน้าขอความยินยอม (PDPA) | PDPA กำหนดให้ขอความยินยอมก่อนเก็บตำแหน่ง และต้องบันทึกสถานะไว้เป็นหลักฐาน ผู้ที่ปฏิเสธยังต้องใช้งานได้ครบทุกฟีเจอร์ | MOU 3.1.3 (1), 3.1.6 (2) |
| 5 | **ความคืบหน้าการเรียน** | ดาวต่อบท สถานะดูวิดีโอจบ และบทที่ปลดล็อกแล้ว | ใช้ทำ Router Guard บังคับลำดับการเรียน (คลิป → เกม → บทถัดไป), แสดงดาวในหน้า Dashboard, ออกใบประกาศเมื่อเรียนครบ และคำนวณอัตราการเรียนจบต่อบท (funnel) | MOU 3.1.3 (2), 3.1.3 (5), 3.1.3 (7) |
| 6 | **ผลการเล่นเกมรายหัวข้อ** | คำตอบรายข้อ ผลถูก/ผิด แยกตามเกมและหัวข้อ | ใช้วัดระดับทักษะใน 3 มิติ (Social Media, Scammer, AI Literacy) และหาโจทย์ที่ตอบผิดมากที่สุด เพื่อให้รู้ว่าประเด็นไหนผู้สูงอายุยังไม่เข้าใจ | MOU 2.3, 3.4, 3.1.3 (7) |
| 7 | **Event log การใช้งาน** (`action_logs`) | การกดปุ่มและพฤติกรรมสำคัญ ส่งแบบ async ไม่บล็อก UI | ใช้ดูความถี่การใช้แต่ละฟังก์ชัน เช่น ปุ่มเสียงอ่าน ปุ่มขยายตัวอักษร หรือการแชร์ เพื่อนำไปปรับปรุงระบบในงวดที่ 2 | MOU 3.1.3 (7), 3.1.6 (4) |

## 3. ข้อมูลที่ห้ามจัดเก็บ

| ข้อมูล | เหตุผล | อ้างอิง |
|---|---|---|
| ชื่อจริง นามสกุลจริง เบอร์โทร และเลขประจำตัวใด ๆ | Anonymity by Default ห้ามมีช่องกรอกในระบบ | MOU 3.1.6 (1) |
| IP ดิบ (Raw IP Address) | ต้องแปลงเป็นจังหวัด/อำเภอที่ edge ก่อนเข้าระบบเสมอ ไม่ให้มี IP ดิบเข้าฐานข้อมูล | MOU 3.1.2, 3.1.6 (3) |
| วันเกิด | เก็บได้เฉพาะช่วงอายุตามหลัก Data Minimization | MOU 3.1.6 (4) |

> **หมายเหตุ:** ชื่อเล่นที่ผู้ใช้ใส่ในใบประกาศใช้สำหรับสร้างภาพในเครื่องเท่านั้น TOR ไม่ได้กำหนดให้เก็บไว้ที่ backend (MOU 3.1.3 (5))

## 4. ข้อกำหนดด้านความปลอดภัยของข้อมูล

- **Row Level Security (RLS):** การเขียนข้อมูล progress และ log ต้องจำกัดให้เฉพาะ session ID ปัจจุบันเขียนได้ ป้องกันการเข้าถึงข้อมูลของผู้อื่น (MOU 3.1.6 (5))
- **Offline-tolerant:** หาก sync ไป backend ล้มเหลวชั่วคราว เกมต้องเล่นต่อได้ ให้เก็บข้อมูลเข้าคิวผ่าน service worker แล้วส่งซ้ำภายหลัง (MOU 3.1.4 (9))
- **Event Logging แบบ async:** การบันทึก log ต้องไม่บล็อก UI (MOU 3.1.3 (7))

## 6. Checklist สิ่งที่ต้องทำ (แยกตามประเภทผลลัพธ์ของงาน)

> - ช่องสถานะ: `☑` = เสร็จแล้ว, `◐` = เสร็จบางส่วน (อธิบายในหมายเหตุ), `☐` = ยังไม่ทำ
> - **ห้ามติ๊ก ☑ โดยไม่มีหลักฐานกำกับ** ให้ใส่ลิงก์ PR ภาพหน้าจอ หรือผลทดสอบไว้ในช่องหมายเหตุ

> - ทุกรายการเป็นข้อกำหนดใน TOR ทั้งหมด Priority จึงบอก **ลำดับที่ควรทำก่อน-หลัง** ไม่ได้บอกว่าข้อไหนข้ามได้
