# ขอบเขตงาน (Terms of Reference: TOR)

จ้างเหมา **พัฒนาเว็บแอปพลิเคชันเชิงโต้ตอบ (Interactive Web Application) พร้อมเกมประกอบสื่อการเรียนรู้เท่าทันสื่อ สำหรับผู้สูงอายุ**

> [ระบุ] — ปรับถ้อยคำ "จ้างเหมา..." ให้ตรงกับประเภทการจัดซื้อจัดจ้างจริงตามระเบียบของหน่วยงาน

## ชื่อโครงการ

**(ภาษาไทย)**
โครงการสร้างเสริมสมรรถนะด้านสื่อสังคมออนไลน์ การหลอกลวงออนไลน์ และการรู้เท่าทันเทคโนโลยีปัญญาประดิษฐ์ สำหรับผู้สูงอายุ และแอดมินโซเชียลมีเดียชุมชน เพื่อยกระดับพฤฒพลังผู้สูงอายุในยุคดิจิทัล

**(ภาษาอังกฤษ)**
Enhancing Social Media Competency, Scam Awareness, and AI Literacy among Older Adults and Community Social Media Administrators to Empower Seniors in the Digital Era

## ที่มาและเหตุผลของโครงการ

โครงการวิจัย **"สร้างเสริมสมรรถนะด้านสื่อสังคมออนไลน์ การหลอกลวงออนไลน์ และการรู้เท่าทันเทคโนโลยีปัญญาประดิษฐ์ สำหรับผู้สูงอายุ และแอดมินโซเชียลมีเดียชุมชน เพื่อยกระดับพฤฒพลังผู้สูงอายุในยุคดิจิทัล"** มีเป้าหมายเพื่อเสริมสร้างภูมิคุ้มกันทางดิจิทัลให้แก่ผู้สูงอายุใน 3 มิติที่สัมพันธ์กัน ได้แก่ ความรู้เท่าทันสื่อสังคมออนไลน์ (Social Media Literacy) ความรู้เท่าทันปัญญาประดิษฐ์ (AI Literacy) และความรู้เท่าทันภัยหลอกลวงออนไลน์ (Scammer Literacy) โดยใช้รูปแบบการแทรกแซง (intervention) ผ่านการพัฒนาศักยภาพ **"วิทยากรระดับชุมชน"** — อาสาสมัครสาธารณสุขประจำหมู่บ้าน (อสม.) เจ้าหน้าที่องค์กรปกครองส่วนท้องถิ่น และแกนนำชุมชน — ให้ทำหน้าที่ส่งต่อความรู้สู่ผู้สูงอายุในพื้นที่ 3 จังหวัดนำร่อง ได้แก่ เชียงใหม่ แพร่ และน่าน

โครงการนี้ใช้งบประมาณส่วนของ **"อบรมเชิงปฏิบัติการในชุมชน" จำนวน 360,000 บาท** และมีกำหนดจะเริ่มใช้งานครั้งแรกกับกลุ่มผู้นำผู้สูงอายุใน 3 จังหวัด ได้แก่ เชียงใหม่ (6–7 สิงหาคม), แพร่ (17–18 สิงหาคม) และน่าน (24–25 สิงหาคม) โดยกรอบระยะเวลาการออกแบบสื่อคือ **กรกฎาคม–ตุลาคม 2569**

โครงการได้จัดทำเนื้อหาวิดีโอแนวตั้งชุด "รู้ทันสื่อ" ไว้แล้ว สำหรับใช้เป็นสื่อหลักในการอบรมและส่งต่อผ่านกลุ่มไลน์ชุมชน เพื่อให้การอบรมมีความน่าสนใจ เข้าถึงง่าย โครงการจึงมีความจำเป็นต้องพัฒนาระบบเว็บแอปพลิเคชันเชิงโต้ตอบ ประกอบเกมย่อยในแต่ละหัวข้อเนื้อหา เพื่อใช้ควบคู่กับวิดีโอชุด "รู้ทันสื่อ" ในกิจกรรมอบรม ทั้งในขั้นอบรมวิทยากรระดับพื้นที่ และขั้นขยายผลสู่ผู้สูงอายุในชุมชน

> [ระบุ] — 360,000 บาท ในเอกสารต้นทางระบุเป็นงบประมาณรวมของ "อบรมเชิงปฏิบัติการในชุมชน" ไม่ได้ระบุแยกเป็นงบพัฒนาระบบ/ซอฟต์แวร์โดยเฉพาะ ควรตรวจสอบและยืนยันวงเงินที่จัดสรรสำหรับงานพัฒนาระบบก่อนใช้อ้างอิงในสัญญา

## วัตถุประสงค์

1. เพื่อพัฒนาเว็บแอปพลิเคชัน (Web Application) สำหรับนำเสนอสื่อการเรียนรู้ชุด "รู้ทันสื่อ" ที่เข้าถึงและส่งต่อได้ง่ายผ่าน LINE รองรับการใช้งานของทั้งวิทยากรระดับชุมชน (อสม./เจ้าหน้าที่ อปท./แกนนำชุมชน) ในขั้นอบรมผู้ถ่ายทอดความรู้ และผู้สูงอายุในขั้นขยายผลสู่ชุมชน
2. เพื่อพัฒนาเกมโต้ตอบ (Interactive Game) ประกอบเนื้อหาแต่ละหัวข้อ ครอบคลุมทั้ง 3 มิติความรู้เท่าทันตามกรอบของโครงการวิจัย ได้แก่ Social Media Literacy, AI Literacy และ Scammer Literacy เพื่อสร้างความสนุกสนานระหว่างการอบรม และเสริมสร้างความตระหนักรู้ (Awareness) ต่อภัยจาก AI และมิจฉาชีพออนไลน์ ผ่านแนวคิด **"หยุด คิด ถาม ทำ"** อันเป็นเครื่องมือสนับสนุนวัตถุประสงค์ข้อ 2.1 ของข้อเสนอโครงการวิจัย
3. เพื่อจัดเก็บข้อมูลการใช้งาน (อายุผู้เล่น ตำแหน่งที่เปิดเล่นแอปพลิเคชัน และผลการทำกิจกรรม/เกมรายหัวข้อ) สำหรับสนับสนุนการติดตามและประเมินผลโครงการ โดยเฉพาะการวัดระดับทักษะการรู้เท่าทันดิจิทัลของผู้สูงอายุและผู้ถ่ายทอดความรู้ ทั้งนี้ข้อมูลที่จัดเก็บควรสามารถเชื่อมโยงหรือส่งออกเพื่อใช้ประกอบแบบประเมินก่อน–หลังการอบรม (Pre/Post Assessment)

## ขอบเขตงาน

### 1. แพลตฟอร์ม

พัฒนาระบบ **Web Application** เชิงโต้ตอบ (Interactive Web Application) รูปแบบ Single Page Application (SPA) ที่เปิดใช้งานผ่านลิงก์ และส่งต่อได้ง่ายผ่าน**แพลตฟอร์มโซเชียลมีเดีย (Social Media Platform)** โดยมีกรอบงานเชิงเทคนิคสำหรับผู้พัฒนาระบบดังนี้:

#### 1.1 ภาพรวมและหลักการออกแบบระบบ

ระบบออกแบบตามหลัก **Mobile-First** โดยมีเป้าหมายให้ผู้สูงอายุและวิทยากรระดับชุมชนเข้าถึงผ่านลิงก์ที่ส่งต่อทางแพลตฟอร์มโซเชียลมีเดียได้ทันที โดยไม่ต้องติดตั้งแอปหรือสมัครสมาชิก (**ไม่มีระบบ login**)

หลักการสำคัญที่ผู้พัฒนาต้องยึดถือตลอดการพัฒนา:

1. **Social Media-first, No-login** — ทุกเส้นทางการใช้งานต้องเปิดได้จากลิงก์เดียว ทำงานได้สมบูรณ์ภายในเบราว์เซอร์ในแอปโซเชียลมีเดีย (In-App Browser/WebView) โดยไม่ต้องออกไปเปิดเบราว์เซอร์อื่นก่อน
2. **Mobile-first, Low-end Device Ready** — ออกแบบและทดสอบบนมือถือ Android ราคาประหยัด/รุ่นเก่า และเครือข่าย 3G/4G ในพื้นที่ห่างไกลเป็นหลัก ไม่ใช่ desktop
3. **Accessibility for Elders (ข้อบังคับ)** — ตัวอักษรใหญ่ ปุ่มกดง่าย คอนทราสต์สูง เสียงอ่านประกอบ ไม่มีเมนูซับซ้อน (รายละเอียดหัวข้อ 1.5)
4. **Privacy by Design (PDPA)** — ไม่เก็บข้อมูลระบุตัวตน เก็บเฉพาะข้อมูลจำเป็นต่อการประเมินผลโครงการ (รายละเอียดหัวข้อ 1.6)

#### 1.3 โครงสร้างฟังก์ชันของระบบ (Functional Modules)

ผู้รับจ้างต้องพัฒนาโมดูลต่อไปนี้ให้ครบถ้วน:

##### 1.3.1 หน้าแรกต้อนรับและขอความยินยอม (Landing & Consent Module)

- หน้าแรกต้อนรับ + ปุ่มเข้าเรียน (สาธารณะ ไม่มี guard)
- หน้าขอความยินยอมเก็บข้อมูล (PDPA) ด้วยภาษาที่เข้าใจง่าย พร้อมปุ่มเลือกช่วงอายุ และยืนยัน/แก้ไขจังหวัด-อำเภอ-ตำบล (ตั้งต้นจาก IP geolocation)
- สร้าง anonymous session id แบบไม่มี login เก็บแบบ **Hybrid Persistence** (localStorage + Cookie, Max-Age 1 ปี, `SameSite=Lax`) เพื่อกันข้อมูลหายเมื่อเบราว์เซอร์ในแอปโซเชียลมีเดีย (In-App WebView) ล้างแคช

##### 1.3.2 ตัวเลือกบทเรียนและระบบจัดลำดับการเรียน (Lesson Selector & Sequence Engine)

- หน้าเลือกบทเรียนแบบ Dashboard แสดงเส้นทางและดาวความคืบหน้า
- อ่านโครงสร้างบทเรียนจาก config/content file (ลำดับ: คลิป → เกม → บทถัดไป)
- รองรับ **Deep Link** เข้าตรงบทเรียน (`/lessons/:id/...`) สำหรับแชร์ผ่านแพลตฟอร์มโซเชียลมีเดีย พร้อมพารามิเตอร์พื้นที่ (เช่น `?ref=facilitator&prov=ChiangMai`)
- Router Guard: บังคับลำดับการเรียน (ต้องได้ดาวบทก่อนหน้าก่อนปลดล็อกบทถัดไป) และบังคับดูวิดีโอจบก่อนเข้าเกม

##### 1.3.3 ตัวเล่นวิดีโอ (Video Player Module)

- ฝังวิดีโอ YouTube แนวตั้ง (9:16) ผ่าน YouTube IFrame API เพื่อดักจับสถานะเริ่มดู/ดูจบ
- Fallback ปุ่ม "เปิดใน YouTube" กรณี embed เล่นไม่ได้ในเบราว์เซอร์/อุปกรณ์บางรุ่น

##### 1.3.4 โมดูลเกม (Game Module)

- โครงสร้างร่วม `GameShell` (โจทย์ทีละข้อ, เฉลยพร้อมคำอธิบาย, progress dots, ปุ่มเสียงอ่าน) + game type plugin ต่อรูปแบบเกม (quiz / tap-to-spot / swipe / scenario / action)
- ข้อมูลโจทย์แยกเป็น content file (JSON) ไม่ผูกกับโค้ด เพื่อให้ทีมเนื้อหาแก้ไข/เพิ่มโจทย์ได้โดยไม่ต้อง build ระบบใหม่
- ทุกเกมต้องไม่มีเงื่อนไข "แพ้" ที่สร้างความอาย — ตอบผิดต้องมีเฉลยพร้อมเหตุผลเสมอ
- เนื้อหาที่สร้างจาก AI ในเกม (ภาพ/เสียง) ต้องมี field เปิดเผยแหล่งที่มา (`ai_disclosure`) แสดง**หลัง**เฉลยเสมอ

##### 1.3.5 ความคืบหน้าและรางวัล (Progress & Reward Module)

- ระบบดาวต่อบทเรียน แสดงผลในหน้าเลือกบทเรียน
- หน้าใบประกาศเมื่อเรียนครบทุกบท (ใส่ชื่อเล่นได้ / render เป็นภาพ / บันทึกลงเครื่อง / แชร์เข้าแพลตฟอร์มโซเชียลมีเดีย)
- ไม่มีระบบคะแนนแข่งขันหรือจับเวลาในโหมดผู้สูงอายุ (ลดความกดดัน)

##### 1.3.6 โหมดวิทยากร (Facilitator Mode)

- เส้นทางแยก (`/facilitator`, `/facilitator/:id`) ไม่ต้องมีระบบสิทธิ์ซับซ้อนในเฟสแรก
- Layout สำหรับจอโปรเจกเตอร์/desktop (ไม่ใช่ mobile layout): วิดีโอขนาดใหญ่ + สคริปต์พูดประกอบต่อบท + ปุ่มควบคุมถัดไป/ย้อนกลับ
- ไม่มี Guard จำกัดลำดับบท — วิทยากรข้ามไปสอนบทใดก่อนก็ได้

##### 1.3.7 การจัดเก็บและวิเคราะห์ข้อมูล (Data Collection & Analytics)

- Session Sync ระหว่าง localStorage และ Cookie อัตโนมัติ
- IP Geolocation Parser — ไม่เก็บ Raw IP Address แต่แปลงเป็นข้อมูลระบุตำแหน่งในระดับจังหวัดและตำบล เพื่อใช้วัดผลการเผยแพร่สื่อในพื้นที่งานวิจัย
- Event Logging (Async, ไม่บล็อก UI) บันทึกการกดปุ่ม/พฤติกรรมสำคัญลง `action_logs`
- แดชบอร์ดสรุปผล: จำนวนผู้เรียนแยกพื้นที่/ช่วงอายุ, อัตราการเรียนจบต่อบท (funnel), โจทย์ที่ตอบผิดมากที่สุด, ความถี่การใช้ฟังก์ชันต่างๆ

#### 1.4 ข้อกำหนดเฉพาะสำหรับการรองรับมือถือและ Social Media Platform

หัวข้อนี้เป็นข้อกำหนดบังคับ (ไม่ใช่ทางเลือก) เนื่องจากกลุ่มเป้าหมายหลักเข้าถึงระบบผ่านมือถือและลิงก์ที่แชร์ผ่านแพลตฟอร์มโซเชียลมีเดียเกือบทั้งหมด:

1. **ทดสอบบน In-App Browser ของแพลตฟอร์มโซเชียลมีเดียจริง เป็นสภาพแวดล้อมหลัก** — ไม่ใช่ desktop Chrome/Safari เพียงอย่างเดียว ต้องยืนยันว่าทุกฟีเจอร์ (วิดีโอ, เกม, แชร์, บันทึกความคืบหน้า) ทำงานได้ปกติภายใน In-App Browser/WebView ของแพลตฟอร์มที่กลุ่มเป้าหมายใช้งานจริง (เช่น LINE)
2. **Deep Link / การแชร์ผ่านโซเชียลมีเดีย** — ทุกบทเรียนและหน้าใบประกาศต้องมีลิงก์ตรงที่แชร์เข้ากลุ่ม/แชทในแพลตฟอร์มโซเชียลมีเดียได้ทันที (เช่น LINE) และเปิดแล้วพาผู้ใช้ไปหน้าปลายทางถูกต้อง (ข้ามหน้าเลือกบทเรียนได้หากมาจากลิงก์เฉพาะ)
3. **กันข้อมูลหายจาก WebView ล้างแคช** — ใช้ Hybrid Persistence (localStorage + Cookie อายุ 1 ปี) พร้อม fallback เป็นพารามิเตอร์ในลิงก์ (เช่น `?prov=ChiangMai`) กรณีอุปกรณ์ล้างข้อมูลทั้งหมด
4. **รองรับอุปกรณ์ปลายทางที่หลากหลาย** — มือถือ Android ราคาประหยัด/รุ่นเก่าเป็นอุปกรณ์อ้างอิงหลัก ไม่ใช่ iPhone/เรือธงรุ่นใหม่
5. **ประสิทธิภาพบนเน็ตช้า** — First load < 3 วินาทีบน 3G, ขนาด asset รวมต่อหน้า < 1MB, โหลดภาพ/เสียงแบบ progressive
6. **แนวตั้งเสมอ (Portrait-first)** — วิดีโอและหน้าจอเกมทุกหน้าออกแบบสำหรับถือมือถือแนวตั้งมือเดียว ไม่ใช่ landscape
7. **ปุ่มกด/พื้นที่แตะ ≥ 48×48px** เว้นระยะห่างชัดเจน เหมาะกับนิ้วผู้สูงอายุ ไม่ใช่ปุ่มขนาด desktop
8. **ไม่บังคับติดตั้งแอปหรือ PWA** — ผู้ใช้ต้องใช้งานได้ครบทุกฟีเจอร์จากการแตะลิงก์เพียงครั้งเดียว การติดตั้ง PWA เป็นเพียงตัวเลือกเสริม
9. **Offline-tolerant ระดับพื้นฐาน** — ไม่บังคับใช้งาน offline เต็มรูปแบบในเฟสแรก แต่เกมต้องเล่นต่อได้แม้ sync ข้อมูลไป backend ล้มเหลวชั่วคราว (คิวข้อมูลผ่าน service worker แล้วส่งซ้ำภายหลัง)

#### 1.5 ข้อกำหนดการเข้าถึงสำหรับผู้สูงอายุ (Accessibility Requirements)

ข้อกำหนดบังคับด้าน UI/UX ที่ผู้พัฒนาต้องนำไปปฏิบัติในทุกหน้าจอ:

| ด้าน                                   | ข้อกำหนด                                                                                                                                |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| ขนาดตัวอักษร                   | เนื้อหาหลัก ≥ 20px, ปุ่ม ≥ 22px และมีปุ่มขยายตัวอักษรได้                                               |
| คอนทราสต์สี                     | อัตราส่วน ≥ 4.5:1 ทุกข้อความ (ตามมาตรฐาน WCAG AA)                                                                 |
| พื้นที่แตะ                       | ปุ่ม/พื้นที่แตะ ≥ 48×48px เว้นระยะห่างกันชัดเจน                                                            |
| การสื่อความหมายด้วยสี | ห้ามใช้สีเป็นตัวสื่อความหมายเดียว (ถูก/ผิดต้องมีไอคอน ✓ ✗ กำกับเสมอ)               |
| เสียงประกอบ                     | ทุกโจทย์/เฉลย (อย่างน้อยเกมกลุ่ม Must) ต้องมีเสียงอ่านประกอบ                                  |
| ภาพเคลื่อนไหว                 | ช้า ชัดเจน ไม่กะพริบเร็ว ไม่มีการจับเวลาบังคับ                                                       |
| การนำทาง                           | เส้นทางเดียวเป็นเส้นตรง ปุ่ม "ถัดไป" ใหญ่ชัด ไม่มีเมนูซ้อน ไม่มี hamburger menu        |
| ภาษา                                   | ประโยคสั้น ภาษาพูด หลีกเลี่ยงศัพท์อังกฤษที่ไม่จำเป็น (ไทยเท่านั้นในเฟสแรก) |

#### 1.6 ความปลอดภัยของข้อมูลและ PDPA

1. **Anonymity by Default** — ห้ามมีช่องกรอกชื่อจริง นามสกุลจริง เบอร์โทร หรือเลขประจำตัวใดๆ ในระบบ
2. **Consent-Based Location** — ต้องมีหน้าขอความยินยอมก่อนเก็บตำแหน่ง; ผู้ปฏิเสธต้องใช้งานแอปได้ครบทุกฟีเจอร์เช่นเดิม และระบบต้องบันทึกสถานะยินยอม/ไม่ยินยอมไว้
3. **ไม่เก็บ Raw IP** — แปลงเป็นจังหวัด/อำเภอที่ edge ก่อนเข้าระบบเสมอ ไม่มี IP ดิบไหลเข้าฐานข้อมูล
4. **Data Minimization** — เก็บเฉพาะช่วงอายุ (ไม่ใช่วันเกิด), ตำแหน่งระดับหยาบ (จังหวัด/ตำบล), ความคืบหน้าการเรียนแบบ anonymous, และ event log การใช้งาน
5. **Row Level Security (RLS)** — การเขียนข้อมูล progress/log ต้องจำกัดให้เฉพาะ session ID ปัจจุบันเขียนได้เท่านั้น ป้องกันการเข้าถึงข้อมูลผู้อื่น

### 2. โครงสร้างเนื้อหา

เนื้อหาแบ่งเป็น "รู้ทันสื่อ" ชุดที่ 1 (เน้นให้ความรู้) จำนวน 3 หัวข้อหลัก:

**หัวข้อที่ 1: Social Media Literacy**

ความเข้าใจพื้นฐานเรื่องสื่อออนไลน์ การตรวจสอบข้อเท็จจริง กลไกการใช้อารมณ์ชักจูงให้เชื่อข่าวปลอม และความปลอดภัย/ความเป็นส่วนตัวของข้อมูลส่วนตัวบนโลกออนไลน์

**หัวข้อที่ 2: Scammer Literacy**

การรู้จักรูปแบบมิจฉาชีพออนไลน์ที่พบบ่อยในกลุ่มผู้สูงอายุ (เช่น phishing, social engineering, romance scam) สัญญาณเตือนที่ควรระวัง แนวทางรับมือด้วยหลัก "หยุด คิด ถาม ทำ" และขั้นตอนการแจ้งเหตุเมื่อถูกหลอก

**หัวข้อที่ 3: AI Literacy**

ความเข้าใจพื้นฐานเกี่ยวกับ AI การสังเกตและรู้เท่าทัน deepfake/สื่อสังเคราะห์/ข้อมูลเท็จที่สร้างจาก AI และประเด็นจริยธรรม/ความเป็นส่วนตัวในการใช้ภาพหรือข้อมูลผู้อื่นกับ Generative AI

ชุดที่ 2 (เชิงทัศนคติ) ใช้แนวคิดหลัก **"หยุด คิด ถาม ทำ"** เชื่อมโยงกับทั้ง 3 หัวข้อข้างต้น

> [ระบุ] — ฉบับแก้ไข (9 ก.ค. 2569) เปลี่ยนชื่อและจัดกลุ่ม 3 หัวข้อหลักให้ตรงกับ 3 มิติของโครงการวิจัย (Social Media Literacy / Scammer Literacy / AI Literacy แทนชื่อเดิม General MIL / Recognizing and Handling Scams / AI and New Technologies) และสรุปเนื้อหาแต่ละหัวข้อแบบย่อ ไม่ได้ระบุรายการหัวข้อย่อย (เช่น ประเภทของ phishing/social engineering หรือประเด็นย่อยของ deepfake) ไว้ในเอกสารต้นทางอีกต่อไป ผู้ออกแบบเนื้อหา/เกมควรยืนยันกับผู้รับผิดชอบโครงการว่ายังต้องอิงรายละเอียดย่อยชุดเดิมประกอบการผลิตหรือไม่

### 3. เกมประกอบการเรียนรู้ (Interactive Game)

- ให้มีเกมย่อยประกอบทั้ง 3 หัวข้อ (Social Media Literacy / Scammer Literacy / AI Literacy) จำนวนอย่างน้อย 6 เกม ให้เหมาะสมกับงบประมาณที่ได้รับ
- รูปแบบการใช้งาน (flow): ผู้เรียนเปิดดูวิดีโอเนื้อหาก่อน ตามด้วยเกมของหัวข้อนั้น แล้วจึงไปยังหัวข้อถัดไป
- เป้าหมายของเกม คือสร้างความตระหนักรู้ (Awareness) ว่าภัยจาก AI และมิจฉาชีพออนไลน์เข้ามาในชีวิตประจำวัน ซึ่งผู้สูงอายุอาจแยกแยะไม่ได้ จึงต้องฝึกให้ระมัดระวังด้วยแนวคิด "หยุด คิด ถาม ทำ" ทุกครั้ง

> [ระบุ] — จำนวน 6 เกม (หัวข้อละ 2 เกม) สอดคล้องกับการประมาณการงบจาก `docs/wiki/tor/TOR_Budget_Worksheet.xlsx` โดยตั้งสมมติฐานว่างบพัฒนาระบบคือ 65% ของ 360,000 บาท (= 234,000 บาท) ซึ่งพอดีกับ WBS รวม 80.3 man-day (รวม Contingency Buffer 10%) แบ่งส่งมอบเป็น 2 ระยะ: ระยะแรก (MVP) หัวข้อละ 1 เกม รวม 3 เกม ก่อนใช้งานจริงที่เชียงใหม่ (6–7 ส.ค. 2569) และระยะที่สองเพิ่มอีกหัวข้อละ 1 เกม รวมเป็น 6 เกม ภายในสิ้นเดือนตุลาคม 2569 ดูรายละเอียดการคำนวณและเงื่อนไขที่ต้องยืนยันเพิ่มเติมที่ [TOR_Budget_Worksheet.md](TOR_Budget_Worksheet.md) — หากสัดส่วนงบ Dev 65% ไม่ได้รับการยืนยัน จำนวนเกมที่เหมาะสมอาจต้องปรับ

### 4. การจัดเก็บข้อมูล

- จัดเก็บข้อมูลอายุผู้เล่น ตำแหน่งที่เปิดเล่นแอปพลิเคชัน (ตำแหน่งทางภูมิศาสตร์) และผลการทำกิจกรรม/เกมรายหัวข้อ เพื่อใช้ติดตามและประเมินผลโครงการ โดยเฉพาะการประเมินระดับทักษะการรู้เท่าทันดิจิทัลของผู้สูงอายุและผู้ถ่ายทอดความรู้ — ข้อมูลควรเชื่อมโยงหรือส่งออกได้เพื่อใช้ประกอบแบบประเมินก่อน–หลังการอบรม (Pre/Post Assessment)
- ดูรายละเอียดเชิงเทคนิคของการจัดเก็บ/วิเคราะห์ข้อมูลและข้อกำหนด PDPA เพิ่มเติมที่หัวข้อ [1.3.7 การจัดเก็บและวิเคราะห์ข้อมูล](#137-การจัดเก็บและวิเคราะห์ข้อมูล-data-collection--analytics) และ [1.6 ความปลอดภัยของข้อมูลและ PDPA](#16-ความปลอดภัยของข้อมูลและ-pdpa)
