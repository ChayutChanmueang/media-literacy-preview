# 🧾 คู่มือกรอกแบบฟอร์มขอใช้เครื่องแม่ข่ายและโดเมนเนม (CAMT)

อ้างอิงจากแบบฟอร์ม "แบบฟอร์มขอใช้เครื่องแม่ข่ายและโดเมนเนม" ของ CAMT — ตารางด้านล่างเรียงตามลำดับช่องกรอกในฟอร์มจริง พร้อมค่าที่แนะนำให้กรอกสำหรับโครงการ **รู้ทันสื่อ Interactive (NAPLAB Media Literacy)**

**ขอบเขตที่จะยื่น:** Domain + เครื่องแม่ข่ายแบบ **Container** (ไม่ใช่แค่ redirect ไป Vercel เหมือนแผนเดิม — ดูเหตุผลใน [README.md](./README.md))

## เหตุผลที่เลือก "Container" แทน "Virtual Machine"

โปรเจกต์เป็น Vite + React SPA (static build) ที่ deploy ผ่าน `npm run build` ได้ไฟล์ static ล้วน ไม่ต้องพึ่ง OS-level dependency พิเศษ หรือ service เสริมนอกเหนือจาก Supabase (ซึ่งเป็น managed service ภายนอกอยู่แล้ว) จึงเหมาะกับ Container มากกว่า VM (เบากว่า ดูแลง่ายกว่า ไม่ต้อง patch OS เอง)

## ร่างข้อความ "เหตุผล/ความจำเป็น"

ใช้ข้อความนี้เป็นฐาน ปรับสำนวนได้ตามความเหมาะสม:

> ขอใช้ subdomain ภายใต้ `ageconnect.camt.cmu.ac.th` และเครื่องแม่ข่ายคอมพิวเตอร์แบบ Container เพื่อโฮสต์เว็บแอปพลิเคชัน "รู้ทันสื่อ Interactive" ซึ่งเป็นเว็บแอปเชิงโต้ตอบ (SPA, mobile-first, ไม่ต้อง login) สำหรับสอนทักษะรู้เท่าทันสื่อ/สแกม/AI ให้ผู้สูงอายุ ผ่านการดูคลิปวิดีโอสั้นสลับกับมินิเกม โครงการมีกำหนดใช้งานจริงครั้งแรกในงานอบรมที่จังหวัดเชียงใหม่ (6–7 ส.ค. 2569) แพร่ (17–18 ส.ค. 2569) และน่าน (24–25 ส.ค. 2569) โดยผู้เข้าร่วมจะเข้าถึงแอปผ่านลิงก์ที่แชร์ในแอป LINE จึงต้องการโดเมนที่สั้น จดจำง่าย และมีความน่าเชื่อถือในฐานะโดเมนของสถาบันการศึกษา เพื่อให้ผู้สูงอายุซึ่งเป็นกลุ่มเป้าหมายหลักเข้าถึงได้ง่ายและมั่นใจในความปลอดภัยของลิงก์

## หลังยื่นคำขอ (ขั้นตอนที่ยังไม่รวมในฟอร์ม)

1. เมื่อได้รับ Container + subdomain จาก CAMT แล้ว ให้เทียบขั้นตอนตั้งค่า DNS/SSL กับแนวทางเดิมใน [dns-setup.md](../dns-setup.md) (อาจต่างจากเดิมเพราะคราวนี้ CAMT เป็นผู้ดูแล DNS **และ** เครื่องแม่ข่ายเอง ไม่ใช่แค่ชี้ CNAME ไป Vercel)
2. ทำตาม [docker-portainer-guide.md](./docker-portainer-guide.md) เพื่อ package image ขึ้น Docker Hub (public ชั่วคราว) แล้ว deploy ผ่าน Portainer ของเครื่องแม่ข่ายที่ได้รับ
3. อัปเดตสถานะ Domain Handoff ใน [sprint-03-polishing.md](../../agile/sprint-backlog/sprint-03-polishing.md) และพิจารณาเปิด user story ใหม่แทน [US-03-R2](../../agile/user-stories/archives/US-03-R2.md) ที่ถูกยกเลิกไปก่อนหน้า
4. บันทึกการเปลี่ยนแปลงใน `docs/changelog.md` ตามธรรมเนียมของโปรเจกต์
