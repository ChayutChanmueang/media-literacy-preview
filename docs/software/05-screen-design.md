# รู้ทันสื่อ Interactive — Screen Design สำหรับผู้สูงวัย

**Version:** 1.3 | **Last Updated:** 2026-08-18 | **Owner:** NAPLAB Dev Team

เอกสารฉบับนี้กำหนดมาตรฐานการออกแบบหน้าจอ (Screen Design) สำหรับผู้ใช้สูงวัย (Elderly UI/UX) ในแอปพลิเคชัน **"รู้ทันสื่อวัยเก๋า" (NAPLAB Media Literacy)** เพื่อแก้ไขปัญหาความสับสนในการใช้งาน และป้องกันไม่ให้ผู้เล่นมองไม่เห็นข้อมูลสำคัญเนื่องจากเลย์เอาต์ยาวเกินหน้าจอ

---

## 1. หลักการ "หน้าเดียว ไม่ต้องเลื่อนจอ" (No-Scroll Viewport Layout Rule)

จากการทดสอบการใช้งานของผู้เล่นสูงวัย พบข้อจำกัดเชิงพฤติกรรมและสรีรวิทยาที่สำคัญ:
* **ความตระหนักรู้ด้านการเลื่อนจอ (Scroll Awareness):** ผู้สูงอายุบางส่วนไม่คุ้นเคยกับการปัดหน้าจอเพื่อดูเนื้อหาด้านล่าง หากเห็นหน้าจอว่างหรือไม่มีสัญลักษณ์ชี้ชัด จะเข้าใจว่าเนื้อหาแสดงครบถ้วนแล้วและติดขัดในการไปต่อ
* **ความแม่นยำในการสัมผัส (Touch Precision):** การใช้ท่าทางปัดเลื่อนหน้าจอมักนำไปสู่ความผิดพลาด เช่น การกดปุ่มโดยไม่ได้ตั้งใจ หรือการปัดไปโดนขอบล่าง/ขอบข้างของ LINE In-App Browser ซึ่งอาจปิดหน้าต่างแอปพลิเคชันลง
* **ขนาดตัวอักษรที่ขยายขึ้น (Font Scaling):** เมื่อผู้ใช้สลับโหมดขนาดตัวอักษรเป็น **วัยเก๋า (A+)** หรือ **ใหญ่พิเศษ (A++)** เนื้อหาจะกินพื้นที่สูงขึ้นประมาณ 15% - 30% ทำให้เกิด Scroll Bar โดยไม่ได้ตั้งใจหากไม่มีการเตรียมการลดรูปเนื้อหา

### 💡 ข้อกำหนดทางเทคนิคและการออกแบบ:
1. **Viewport Lock (100vh):** ความสูงของแต่ละหน้าจอต้องถูกจำกัดให้พอดีกับหน้าต่างเบราว์เซอร์พอดี โดยใช้ CSS `height: 100dvh` (Dynamic Viewport Height เพื่อหักลบแถบเครื่องมือของ LINE browser ออกอัตโนมัติ) และตั้งค่า `overflow: hidden` ในระดับคอนเทนเนอร์หลัก
2. **Flexible Flexbox layout:** จัดเรียงวัตถุในแนวตั้งโดยใช้ Flexbox (`flex-direction: column`) ร่วมกับการใช้ `justify-content: space-between` หรือ `space-around` เพื่อให้พื้นที่หด/ขยายตัวตามความสูงหน้าจอของมือถือรุ่นต่างๆ
3. **การ์ดและระยะห่างปรับเปลี่ยนได้ (Fluid Spacing):** การกำหนด padding และ margin ให้ใช้หน่วย `%`, `vh` หรือแบบยืดหยุ่นแทนค่าคงที่ (px) เพื่อช่วยให้หน้าจอขนาดเล็กรุ่นประหยัดยังคงแสดงผลได้ครบถ้วน
4. **ลำดับการแสดงผลเดี่ยว (Single-focus Flow):** แต่ละหน้าจอจะต้องนำเสนอเป้าหมายเพียงเรื่องเดียว (One Goal Per Screen) ไม่ซ้อนภารกิจเพื่อให้ลดความหนาแน่นของข้อมูล

## 2. ตารางการคัดเลือกและตัดเนื้อหา (Content Prioritization Matrix)

เพื่อรักษาขีดจำกัดความสูงหน้าจอ 100dvh จึงมีความจำเป็นต้อง **"คัดออก"** หรือ **"ลดรูป"** ข้อมูลที่ไม่ส่งผลต่อกระบวนการเรียนรู้หลัก (Core Loop: ต้อนรับ → ยินยอม → เลือกบท → ดูคลิป → เล่นเกม → รับรางวัล/ใบประกาศ) ดังตารางเปรียบเทียบต่อไปนี้:

| หน้าจอ (Screen) | ส่วนที่ต้องรักษาไว้ (Must Keep - Core) | ส่วนที่แนะนำให้ตัดออก (Must Cut - Secondary) | วิธีการจัดการส่วนที่ตัดออก / ล้นหน้าจอ |
|:---|:---|:---|:---|
| **`/` LandingWelcome** | • ชื่องาน/โครงการหลัก<br>• สโลแกนประจำจังหวัด<br>• ปุ่มหลัก "เริ่มเรียนรู้" (CTA ใหญ่)<br>• ตัวเลือกเปลี่ยนจังหวัด/ธีมสี | • ประวัติผู้สนับสนุนโครงการ<br>• รายชื่อผู้วิจัย/คณะทำงาน<br>• ลิงก์โซเชียลมีเดียอื่นๆ ของสถาบัน | ย้ายข้อมูลผู้สนับสนุนและผู้วิจัยไปไว้ในหน้าย่อย "เกี่ยวกับโครงการ" (About) โดยกดเปิดเป็น Dialog แบบเต็มจอเฉพาะเมื่อสนใจ |
| **`/consent` OnboardingConsent** | • สรุปข้อตกลง PDPA สั้นๆ (1-2 ประโยค)<br>• ตัวเลือกช่วงอายุ (ปุ่มกดขนาดใหญ่)<br>• ปุ่มยืนยันพิกัดจังหวัด/อำเภอ/ตำบล<br>• ปุ่มกด "ยินยอมและเริ่มใช้งาน" | • ข้อความกฎหมาย PDPA ตัวเต็มที่มีความยาว<br>• ลิงก์นโยบายความเป็นส่วนตัวภายนอกเว็บ | แสดงสรุปภาษาพูดที่เข้าใจง่ายกลางจอ และมีปุ่มลิงก์สไตล์ Text-link เล็กๆ ด้านล่างสำหรับเปิดดูเอกสารกฎหมายตัวเต็มในรูปของ Modal popup |
| **`/lessons` LessonSelector** | • แถบหัวแสดงชื่อบทเรียนสะสมดาว<br>• สกอร์บอร์ดจำนวนดาวรวม (🌟 X/5)<br>• การ์ดบทเรียนหลัก (แสดงบท 1-3 ชัดเจน)<br>• แถบสวิตช์ปรับขนาดฟอนต์ (A/A+/A++) | • คำอธิบายเนื้อหาบทเรียนอย่างย่อ<br>• คะแนนเฉลี่ยของผู้เล่นท่านอื่น<br>• สถิติชั่วโมงที่ใช้เรียนสะสม | แสดงผลบทเรียนในรูปแบบการ์ดสั้นๆ (รูป + ลำดับบท + เครื่องหมายสัญลักษณ์ล็อก/ปลดล็อก) หากมีจำนวนบทเรียนมากเกิน 3 บท ให้ใช้การเลื่อนในตาราง Grid แบบแถวเดี่ยวแนวนอน (Horizontal Slider) หรือระบบแบ่งหน้าย่อย (Pagination) แทนการเลื่อนจอลงด้านล่าง |

## 3. รายละเอียดการลดรูปและดีไซน์รายหน้าจอ (Screen-by-Screen Breakdown)

เพื่อให้เห็นรูปแบบของการจัดวางโดยไม่ต้องเลื่อนหน้าจอ รายละเอียดโครงสร้างแบบ 100dvh ของแต่ละหน้าจอหลักมีดังนี้:

### 3.1 หน้าแรกต้อนรับ (`/` - LandingWelcome)
* **การจำกัดพื้นที่:** ใช้สีพื้นหลัง Gradient ตามธีมประจำจังหวัด แบ่งสัดส่วนความสูงเป็น 3 ส่วนหลัก (Header 25% / Logo & Content 50% / Action Footer 25%)
* **การคัดออก:**
  * ยุบส่วนท้ายของเว็บ (Standard Footer) เช่น ลิงก์นโยบาย, โครงสร้างแผนผังเว็บ และประวัติมหาวิทยาลัย ย้ายไปซ่อนในสัญลักษณ์เครื่องหมายคำถาม (?) เล็กๆ บนมุมขวาบน ซึ่งจะเปิดข้อมูลเครดิตผู้สนับสนุนในรูปแบบ **Credit Sheet Overlay** (สไลด์ขึ้นมาจากขอบล่างของหน้าจอโดยไม่เปิดหน้าใหม่)
* **การจัดการ Layout เมื่อขยายฟอนต์ใหญ่ (A++):**
  * รูปภาพหลัก (Illustration) จะลดขนาดลงแบบอัตโนมัติ (`max-height: 25dvh`) เพื่อคืนพื้นที่ให้กับข้อความพาดหัวที่มีขนาดใหญ่ขึ้น

```
+-----------------------------------+
| [Region Theme Tag]            (?) | <-- กดเพื่อดูผู้สนับสนุน (Modal)
|                                   |
|       [Logo โครงการ]              | <-- หด/ขยายขนาดอัตโนมัติตามความสูงจอ
|  "สานพลัง สังคมสูงวัย ใส่ใจสุขภาพ" |
|                                   |
|     ยินดีต้อนรับสู่วัยเก๋ารู้ทันสื่อ |
|                                   |
|   +---------------------------+   |
|   |    เริ่มเรียนรู้และเล่นเกม    |   | <-- ปุ่มหลักสัมผัสง่าย (ความสูง 64px)
|   +---------------------------+   |
+-----------------------------------+
```

### 3.2 หน้ายินยอมและเลือกพื้นที่ (`/consent` - OnboardingConsent)
* **การจำกัดพื้นที่:** แบ่งพื้นที่จอเป็น: ข้อความสรุปข้อตกลงและนโยบายความเป็นส่วนตัว (30%) -> แบบสอบถามข้อมูลพื้นฐาน (อายุ/พื้นที่) (45%) -> ปุ่มกดยืนยัน (25%)
* **การคัดออก:**
  * ห้ามแสดงเอกสารเงื่อนไขกฎหมาย 5 หน้ากระดาษลงในหน้านี้โดยตรง ให้แสดงเฉพาะ **"ข้อสรุปความปลอดภัย 3 ข้อสำคัญ"** ด้วยภาษาที่ชาวบ้านเข้าใจง่าย (เช่น ข้อมูลนี้จะปลอดภัย, ใช้เพื่อการศึกษาในจังหวัดท่านเท่านั้น, และลบข้อมูลหลังจบกิจกรรม)
  * ไม่มีปุ่มดึงพิกัด GPS — ผู้เรียนเลือกจังหวัด/อำเภอ/ตำบลเอง เพราะพิกัดมักไม่ตรง และอาจต้องการกรอกบ้านเกิดหรือที่อยู่ปัจจุบันตามความประสงค์ ([FB-2026-08-18](../agile/feedback/FB-2026-08-18-gps-consent.md))
* **การจัดการ Layout เมื่อขยายฟอนต์ใหญ่ (A++):**
  * ตัวเลือกช่วงอายุเปลี่ยนจากปุ่มวงกลมแนวตั้งยาวเหยียด เป็นปุ่มกดรูปแบบ Grid 2 คอลัมน์แทน เพื่อให้ไม่ต้องล้นขอบจอ

```

|  [อ่านนโยบายฉบับเต็ม]                 | <-- ลิงก์เปิดเอกสารตัวเต็มใน Modal

|  +---------------+ +---------------+|

### 3.3 หน้าเลือกบทเรียน (`/lessons` - LessonSelector)
* **การจำกัดพื้นที่:** โครงสร้าง 3 ส่วน (Header & Stars 15% / Scrollable Row 65% / Accessibility Controls 20%)
* **การคัดออก:**
  * ตัดข้อความเกริ่นนำของบทเรียนแต่ละบทออก เหลือเพียงรูปภาพสัญลักษณ์ประจำด่าน (เช่น ไอคอน LINE, ไอคอนรูปสายโทรศัพท์, ไอคอนซองจดหมาย) ตัวเลขอักษรด่าน และความคืบหน้าดวงดาว (🌟) เท่านั้น
* **การจัดการ Layout เมื่อขยายฟอนต์ใหญ่ (A++):**

### 3.8 หน้ากระดานคะแนน (`/lessons/:id/leaderboard` - LessonLeaderboardPage)
* **ขอบเขตของ draft:** ใช้ภาพร่างเป็น reference เฉพาะ layout, สัดส่วน และลำดับข้อมูล ไม่ใช้สี, เงา, typography หรือ artwork ตามภาพ ให้ใช้ `AppLayout` และ design tokens ของธีมปัจจุบันทั้งหมด
* **State A — กรอกชื่อ:** วางการ์ดหัวข้อ "กรอกชื่อเพื่อเก็บคะแนน" และช่องชื่อไว้กึ่งกลาง; ปุ่มใหญ่สองปุ่มอยู่แถบล่างติดจอแบบมินิเกม
  * **ไม่เก็บคะแนน:** เปิด popup ถาม "ไม่ต้องการเก็บคะแนนหรือไม่?" — กด "ใช่" จึงเข้าดูอันดับแบบ browse-only โดยไม่สร้าง local player profile และไม่ส่งคะแนน; กด "ไม่ใช่" ปิด popup แล้วอยู่ในหน้ากรอกชื่อ
  * **เก็บคะแนน:** disabled จนกว่าชื่อจะผ่าน validation; เมื่อกดให้เปิด popup ถาม "ต้องการเก็บคะแนนหรือไม่?" — กด "ใช่" จึงสร้าง local profile แล้วเปิดกระดานคะแนน; กด "ไม่ใช่" ปิด popup แล้วอยู่ในหน้ากรอกชื่อ
  * หาก local player profile ถูกต้อง ต้องข้าม State A โดยอัตโนมัติ
* **State B — กระดานคะแนน:** เรียงส่วนประกอบจากบนลงล่างเป็นชื่อเกมจาก route → แคปซูลชื่อผู้เล่น + คะแนนรอบนี้ → หัวตาราง `อันดับ | ชื่อ | คะแนน` → รายการ Top 10 แบบการ์ดแนวตั้ง; ปุ่มกระทำอยู่แถบล่างติดจอแบบมินิเกม ไม่ซ้อนในรายการ
  * เมื่อเก็บคะแนนแล้ว: ปุ่มเดียว "เสร็จสิ้นบทเรียน"
  * เมื่อดูแบบไม่เก็บคะแนน: สองปุ่มติดกัน "กรอกชื่อเพื่อเก็บคะแนน" | "เสร็จสิ้นบทเรียน"
  * ไม่มีปุ่ม "อัปเดตคะแนน" ในแถบนี้; หากโหลดไม่สำเร็จใช้ปุ่ม "ลองใหม่" ใน error card
* **State C — Browse จากเมนู (US-CF-52):** เข้าจากปุ่ม "กระดานคะแนน" ใน drawer → popup เลือกเกม (`LeaderboardGamePicker`, slot = ไอคอน + ชื่อเกม) → เปิดหน้าแบบ spectator (`?view=browse`): เหรียญบนเป็น 🏆 trophy, ไม่มีแคปซูลชื่อผู้เล่นและไม่ไฮไลต์แถว; ปุ่มล่างเป็น "เลือกเกม" เปิด popup สลับเกม
* **การแยกเกม:** derive `gid` จาก `:id` ของ route และแสดงเฉพาะคะแนนเกมนั้น; การสลับเกมทำผ่าน popup เลือกเกม (เฉพาะโหมด browse) ไม่มี tab/dropdown ในตัวหน้า
* **รูปแบบแต่ละแถว:** คอลัมน์อันดับกว้างคงที่, ชื่อใช้พื้นที่ยืดหยุ่นและตัดด้วย ellipsis หนึ่งบรรทัด, คะแนนอยู่ใน pill ด้านขวา
* **อันดับ 1–3:** ใช้ตัวเลขร่วมกับ icon หรือ CSS badge ได้ ไม่ต้องสร้างหรือนำเข้าไฟล์ artwork เหรียญใหม่
* **รายการของผู้เล่นปัจจุบัน:** ใช้กรอบและป้าย "คุณ" ร่วมกัน ห้ามใช้สีอย่างเดียว และอาจมีหลายแถวเพราะระบบเก็บ history ทุกครั้งที่เล่น
* **การเรียงข้อมูล:** คะแนนในภาพ draft เป็นข้อมูลตัวอย่างเท่านั้น ระบบจริงต้องเรียง `score desc` และใช้ `created_at asc` เป็น tie-break
* **Empty state:** หากเกมนั้นยังไม่มีคะแนน ให้แสดงข้อความเชิงเชิญชวนและปุ่ม "ไปเล่นเกมนี้" แทนตารางว่าง
* **Error state:** ใช้ข้อความภาษาง่าย พร้อมปุ่ม "ลองใหม่" โดยไม่ล้าง UUID หรือชื่อจากเครื่อง
* **Accessibility:** ตัวอักษรทุกส่วน ≥ 20px, touch target ≥ 48×48px, contrast ≥ 4.5:1 และใช้ `overflow-y-auto` + inner `min-h-full` เพื่อให้เลื่อนได้บนจอเตี้ยหรือเมื่อขยายฟอนต์

## 4. แนวทางการนำไปประยุกต์ใช้ใน CSS & React

เพื่อบังคับใช้กฎนี้ในการพัฒนา Frontend โค้ดของนักพัฒนาควรเป็นดังนี้:

### 4.1 CSS กำหนดความสูงและปิดการเลื่อน (Container Lock-in)
ในการสร้าง Screen Shell ให้บังคับใช้สไตล์เพื่อจำกัดความสูงและปิดกั้น scroll-bar ด้านนอกสุดเสมอ:

```css
/* src/styles/senior-layout.css */

.senior-screen-container {
  width: 100%;
  max-width: 480px;         /* ล็อคขนาดความกว้างตาม Device Token */
  height: 100dvh;           /* ล็อคความสูงหน้าจอให้พอดี Viewport ของเบราว์เซอร์ */
  margin: 0 auto;
  overflow: hidden;         /* ปิด Scroll bar ระดับหน้าเว็บหลัก */
  display: flex;
  flex-direction: column;
  justify-content: space-between;
  box-sizing: border-box;
  padding: 24px;            /* กำหนด Margin ภายในให้ระยะแตะปลอดภัย */
  position: relative;
  background-color: var(--bg-card);
}

/* ส่วนแสดงคอนเทนต์ที่อาจจำเป็นต้องเลื่อนภายในกล่องเฉพาะ */
.senior-scrollable-box {
  flex-grow: 1;
  overflow-y: auto;         /* ยินยอมให้เลื่อนในกล่องจำกัดเฉพาะกรณีจำเป็น */
  max-height: 40dvh;        /* บังคับไม่ให้กล่องคอนเทนต์ยาวดึงเลฟเอาต์โดยรวมเสีย */
  scrollbar-width: thin;
  margin-bottom: 16px;
}
```

### 4.2 React Component Shell Template
โครงสร้าง Component ที่สอดคล้องกับแนวทาง "หน้าเดียวเสร็จสิ้น":

```jsx
// src/components/senior/SeniorScreenShell.jsx
import React from 'react';
import '../../styles/senior-layout.css';

export const SeniorScreenShell = ({ children, header, footer }) => {
  return (
    <div className="senior-screen-container">
      {/* Header Section (ฟิกซ์ด้านบน ไม่ขยับ) */}
      <header className="senior-screen-header" style={{ flexShrink: 0 }}>
        {header}
      </header>

      {/* Main Body Content Section (หดขนาดพื้นที่อัตโนมัติ) */}
      <main className="senior-screen-main" style={{ flexGrow: 1, display: 'flex', flexDirection: 'column', justifyContent: 'center' }}>
        {children}
      </main>

      {/* Footer Actions Section (ฟิกซ์ปุ่มไว้ที่ล่างสุดเสมอ) */}
      <footer className="senior-screen-footer" style={{ flexShrink: 0, marginTop: 'auto' }}>
        {footer}
      </footer>
    </div>
  );
};
```
