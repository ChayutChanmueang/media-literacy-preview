### 1. 🔴 [ทุกเกม] วิดีโอคำอธิบายแสดง **หลัง** เล่นเกม — ต้องแก้

**คำอธิบาย:**  
ขณะนี้วิดีโอคำอธิบายของทุกเกมถูกเรียกแสดงผล *หลัง* จากที่ผู้ใช้เล่นเกมไปแล้ว แทนที่จะแสดงก่อน ส่งผลให้ flow การเรียนรู้ที่ตั้งใจไว้เสียหาย และอาจทำให้ผู้สูงอายุที่ทำกิจกรรมเสร็จแล้วเกิดความสับสน

**ความสำคัญ:** ต้องแก้

**ความครอบคลุมที่มีอยู่:** ❌ ยังไม่มีการบันทึกไว้อย่างชัดเจนใน sprint หรือ user story ปัจจุบัน

> **สิ่งที่ต้องทำ:** ตรวจสอบ logic การเรียกวิดีโอในทุก game component ซึ่งน่าจะเกี่ยวข้องกับลำดับการเปลี่ยนจากเกมไปวิดีโอใน Flow ดูเพิ่มเติม: [US-FLOW-01](../user-stories/US-FLOW-01.md) และ [US-VIDEO-01](../user-stories/US-VIDEO-01.md)

**คำอธิบาย:**  
ปัจจุบันผู้เล่นสามารถกดข้ามวิดีโอคำอธิบายได้ทันทีโดยไม่จำเป็นต้องดูให้จบแม้แต่ครั้งเดียว พฤติกรรมที่ต้องการคือ วิดีโอต้องถูกดูจนจบอย่างน้อยหนึ่งครั้ง ก่อนที่ปุ่มเล่น/ข้ามจะถูกเปิดใช้งาน

**ความสำคัญ:** ควรแก้

**ความครอบคลุมที่มีอยู่:**

> **สิ่งที่ต้องทำ:** แก้ไข Acceptance Criteria ของ [US-VIDEO-01](../user-stories/US-VIDEO-01.md) ให้กำหนดว่า ผู้ใช้ต้องดูวิดีโอจนจบในการรับชมครั้งแรก จึงจะสามารถกดปุ่ม "ต่อไป" ได้ พฤติกรรมการข้ามควรเปิดใช้งานตั้งแต่การรับชม **ครั้งที่สอง** เป็นต้นไปเท่านั้น

### 5. 🟡 [G6] หน้าเฉลย/Solution แสดงสั้นเกินไป — ควรแก้

**คำอธิบาย:**  
หน้าเฉลย (Solution/Answer Reveal) ของ G6 แสดงในระยะเวลาสั้นเกินไป ผู้สูงอายุอาจ:
- อ่านเคล็ดลับไม่ทันเพราะหน้าจอเปลี่ยนไปก่อน
- รู้สึกหงุดหงิดเพราะหน้าจอเปลี่ยนก่อนที่จะรับรู้เนื้อหาได้
- เพิกเฉยต่อเคล็ดลับเพราะไม่มีเวลาเพียงพอในการอ่าน

**ความสำคัญ:** ควรแก้

**ความครอบคลุมที่มีอยู่:**  
[US-GAME-06-R1](../user-stories/US-GAME-06-R1.md) AC `[x]` ระบุว่า:  
> *"ปุ่ม 'สถานการณ์ถัดไป' auto-advance **5 วิ** + แถบ progress บนปุ่ม"*

5 วินาทีน่าจะไม่เพียงพอสำหรับผู้สูงอายุในการอ่านคำอธิบาย component `AutoAdvanceButton` (ใช้ร่วมกันระหว่าง G1/G3/G6) รับค่า `delayMs` เป็น parameter ที่ปรับได้

> **สิ่งที่ต้องทำ:** เพิ่มระยะเวลา auto-advance ของหน้าเฉลยใน G6 แนะนำให้ใช้ **15–20 วินาที** (ใกล้เคียงกับ delay ของหน้าวิดีโอใน [US-VIDEO-01](../user-stories/US-VIDEO-01.md)) เพื่อให้ผู้สูงอายุมีเวลาอ่านเพียงพอ อัปเดต [US-GAME-06-R1](../user-stories/US-GAME-06-R1.md) และ call `AutoAdvanceButton` ใน `G6LineSimulation.jsx` ด้วยค่า `delayMs` ใหม่

### 7. 🟢 [UI] UI รู้สึกอึดอัดแม้ตั้งฟอนต์เล็กที่สุด — ความสำคัญต่ำ

**คำอธิบาย:**  
แม้จะตั้งขนาดฟอนต์เล็กที่สุด UI โดยรวมยังรู้สึกอึดอัดและแน่น แนวทางแก้ไขที่เสนอ ได้แก่ ลดขนาด element ของ UI หรือเพิ่ม spacing/padding เพื่อให้ layout โล่งขึ้น

**ความสำคัญ:** ความสำคัญต่ำ (nice to have)

**ความครอบคลุมที่มีอยู่:**  
เรื่องนี้อยู่ในขอบเขตของ [US-UX-05](../user-stories/US-UX-05.md) โดยตรง — *"ทำเกมให้ Responsive และนำ Design จาก UX/UI มาใช้จริง"* — ซึ่งมุ่งเป้าที่ layout แบบ single-screen บนอุปกรณ์ทุกขนาด Acceptance Criteria (#1) กำหนดให้ทุกเกมผ่าน audit `zero-scroll-ui`

นอกจากนี้ การรองรับระดับฟอนต์ `data-size` และระบบ responsive token เป็นส่วนหนึ่งของงานใน Sprint 08 ผ่าน [US-GAME-01-R1](../user-stories/US-GAME-01-R1.md), [US-GAME-03-R1](../user-stories/US-GAME-03-R1.md) และ [US-GAME-06-R1](../user-stories/US-GAME-06-R1.md)

> **สิ่งที่ต้องทำ:** บันทึกเป็น sub-task เรื่อง UI spacing ภายใต้ [US-UX-05](../user-stories/US-UX-05.md) ตรวจสอบค่า padding/margin เมื่อฟอนต์อยู่ที่ขนาดเล็กที่สุด (`data-size=small`) สามารถเลื่อนออกไปทำได้หลังงาน responsive layout หลักเสร็จสิ้น

### 8. 🟢 [Infra] Cloudflare ถามยืนยันตัวตนบ่อยเกินไป + ปัญหาสองแท็บ — ความสำคัญต่ำ

**คำอธิบาย:**  
ระบบ Cloudflare Security Check (CAPTCHA / bot verification) ปรากฏขึ้นบ่อยเกินไประหว่างการใช้งาน นอกจากนี้ยังพบว่าบางครั้งเกมถูกเปิดในสองแท็บแยกกัน ซึ่งส่งผลให้ Cloudflare ตรวจจับว่าเป็นการใช้งานผิดปกติและขอให้ผู้ใช้ยืนยันซ้ำอีกครั้ง พฤติกรรมนี้รบกวนประสบการณ์ผู้สูงอายุที่อาจไม่คุ้นเคยกับขั้นตอน CAPTCHA

**ความสำคัญ:** ความสำคัญต่ำ (จะดีมากถ้าได้รับการแก้ไข)

**Existing Coverage:** ❌ ยังไม่มีการบันทึกใน user story หรือ sprint backlog ใด ๆ  
เรื่องความปลอดภัยโครงสร้างพื้นฐานที่ใกล้เคียงที่สุดคือ [US-SEC-01](../user-stories/US-SEC-01.md) แต่ครอบคลุมเฉพาะ credential rotation, API auth และ quiz integrity — ไม่ครอบคลุมการตั้งค่า Cloudflare

> **สาเหตุที่เป็นไปได้:**
> - Cloudflare Turnstile / Bot Fight Mode ตั้งค่า sensitivity สูงเกินไปสำหรับ traffic จาก LINE in-app browser
> - การเปิดเกมผ่านลิงก์ LINE อาจเปิด session ใหม่ทุกครั้ง ทำให้ Cloudflare มองว่าเป็น bot
> - ผู้ใช้บางรายกด back แล้ว forward ทำให้หน้าโหลดซ้ำหลายครั้ง

> **สิ่งที่ต้องทำ:** ตรวจสอบการตั้งค่า Cloudflare Security Level สำหรับ domain ของโปรเจกต์ พิจารณา:
> 1. ลด Bot Fight Mode sensitivity สำหรับ traffic จาก LINE browser (UA whitelist หรือ custom rule)
> 2. ตรวจสอบว่ามีการเปิดซ้ำหลายแท็บจาก flow ของแอปหรือไม่ (เช่น การ redirect จาก LINE)
> 3. สร้าง User Story ใหม่ (เช่น `US-INFRA-01`) เพื่อ track การแก้ไขอย่างเป็นระบบ

### 10. 🔴 [G1/G3/G6] ด่านควรสุ่มลำดับในแต่ละรอบ — ควรแก้

**คำอธิบาย:**  
ปัจจุบันโจทย์/สถานการณ์ใน G1, G3 และ G6 แสดงตามลำดับคงที่ทุกครั้ง ทำให้ผู้เล่นที่เล่นซ้ำหลายรอบจดจำลำดับได้และไม่ได้ฝึกคิดวิเคราะห์อย่างแท้จริง

**ความสำคัญ:** ควรแก้

**Existing Coverage:** ❌ ยังไม่มีการบันทึกใน user story ใด ๆ ในปัจจุบัน

> **สิ่งที่ต้องทำ:** เพิ่ม shuffle function (`Fisher-Yates` หรือ utility ที่มีอยู่แล้วในโค้ด) สำหรับ:
> - **G1:** shuffle `QUESTIONS` array ใน `G1FactCheck.jsx` ก่อนเริ่มเกม (เช่น `useMemo` เมื่อ mount)
> - **G3:** shuffle `QUESTIONS` (หรือ sub-pool 3 ข้อจาก pool 6 ข้อ) ใน `G3AIOrNot.jsx`
> - **G6:** shuffle `SCENARIOS` array ใน `G6LineSimulation.jsx` ก่อนเริ่มเกม
>
> หากข้อ 9 แก้ G3 ให้เหลือ 6 ข้อไว้เป็น pool และสุ่ม  3 ข้อในแต่ละรอบ สามารถแก้ข้อ 9 และ 10 ได้พร้อมกัน

### 11. 🔴 [G13] อยากให้เพิ่มเสียง Effect และ BG (BGM/SFX) — ควรแก้

**คำอธิบาย:**

**ความสำคัญ:** ควรแก้

**ความครอบคลุมที่มีอยู่:** ❌ ยังไม่มีการบันทึกไว้ใน user story หรือ sprint backlog ปัจจุบัน  
[US-GAME-13-R2](../user-stories/US-GAME-13-R2.md) เน้นที่ระบบเกมเพลย์หลักบน Canvas 2D และ physics แต่ยังไม่ได้ระบุระบบเสียง SFX/BGM

> **สิ่งที่ต้องทำ:**
