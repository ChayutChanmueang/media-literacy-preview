## 📋 รายละเอียดผลตอบรับ

---

### 1. 🟡 [ทั้งแอป] ฟอนต์ถูกขยายซ้ำจากการตั้งค่าของเครื่อง/เบราว์เซอร์ ทำให้ Layout เพี้ยน — ควรแก้

**คำอธิบาย:**
มือถือของผู้สูงอายุมักถูกตั้งขนาดฟอนต์ของระบบให้ใหญ่เพื่ออ่านง่าย เมื่อเปิดแอป (ซึ่งออกแบบให้ฟอนต์ใหญ่พอดีสำหรับผู้สูงวัยอยู่แล้ว ตามกติกา $\ge 20\text{px}$ ใน `AGENT.md`) ฟอนต์จะถูก **คูณขนาดซ้ำอีกชั้น** ทำให้เลย์เอาต์แบบ zero-scroll เพี้ยน — ข้อความล้นกรอบ, ปุ่มขยายจนดันเนื้อหาตกจอ (เช่นหน้า Landing: โลโก้เท่าเดิมแต่ตัวหนังสือโตจนปุ่ม "กดที่นี่เพื่อเริ่ม" กินพื้นที่และล้น)

ต้องการให้ **ตรึงขนาดฟอนต์ให้คงที่ตามที่ออกแบบ** ไม่ให้การตั้งค่าขยายฟอนต์ของเครื่องมาทำให้ layout พัง (ผู้ใช้ยังปรับขนาดผ่านปุ่มปรับขนาดในแอปเอง — `data-size` ปกติ/ใหญ่/ใหญ่มาก — ได้ตามปกติ)

**ความสำคัญ:** ควรแก้ (กระทบการใช้งานจริงของกลุ่มเป้าหมายโดยตรง)

**ความครอบคลุมที่มีอยู่:**
- แอปมี `<meta viewport>` ล็อก `maximumScale:1, userScalable:false` (`src/app/layout.tsx`) และฟอนต์ส่วนใหญ่เป็นหน่วย `px` อยู่แล้ว
- `src/app/globals.css` เดิมมี `-webkit-text-size-adjust: none` (เพิ่มไว้ตั้งแต่ commit `2d4c6cd`, 2026-07-30)
- ปุ่มปรับขนาดฟอนต์ในแอป (`data-size`) มีอยู่แล้วเป็นตัวควบคุมหลักสำหรับผู้สูงวัย

**ผลการตรวจสอบ (Root Cause):**
มีกลไกขยายฟอนต์ **2 แบบที่คนละเรื่องกัน**:

| กลไก | ที่มา | กันได้ด้วย CSS ไหม |
|------|-------|--------------------|
| **OS / ระบบตั้ง Font ใหญ่** | Settings → Display → Font size ของเครื่อง | ✅ ได้ ด้วย `text-size-adjust` |
| **Chrome in-browser "Text scaling"** | Chrome → Settings → Accessibility → Text scaling | ❌ ไม่ได้ — Chrome จงใจไม่ให้เว็บ override (ถือเป็น accessibility preference ของผู้ใช้) |

**สิ่งที่ทำไปแล้ว (✅ ได้ผล):**
- เปลี่ยน `src/app/globals.css` จาก `text-size-adjust: none` → **`100%`** และขยาย selector เป็น `html, body`
  (ค่า `100%` ที่ระบุชัดเจน Chrome/Android honor เสถียรกว่า `none` ในการตรึงขนาด)
- **ทดสอบบนเครื่องจริง: ตั้ง OS font ใหญ่สุดแล้ว layout ยังคงปกติเป๊ะ** — แก้เคส OS font scale สำเร็จ ซึ่งเป็นเคสที่ผู้สูงอายุพบบ่อยที่สุด

**สิ่งที่ยังแก้ไม่ได้ (❌ ข้อจำกัดเบราว์เซอร์):**
- **Chrome in-browser "Text scaling" slider** ยังขยายฟอนต์อยู่ ไม่ว่าจะตั้ง `text-size-adjust` เป็น `none` หรือ `100%` เพราะ Chrome **จงใจ** ไม่ให้ CSS ปิดกลไกนี้
- เคยลองทำ JS วัดตัวคูณ (probe) แล้วหักกลับด้วย `zoom` แต่ Chrome Text Autosizing ไม่ assign ตัวคูณให้ element ที่ insert-วัด-ลบ ภายใน tick เดียว (คำนวณตอน layout pass จริงเท่านั้น) ทำให้วัดค่าไม่ได้อย่างน่าเชื่อถือโดยไม่เพิ่มความซับซ้อนมาก → **ถอดออก คงเฉพาะส่วนที่พิสูจน์แล้วว่าได้ผล**

**การตัดสินใจ / เหตุผล:**
รับข้อจำกัดของ Chrome slider ไว้ เพราะ (1) เป็นเคสที่ผู้ใช้ต้องตั้งใจเข้าไปตั้งในเมนู Accessibility ของเบราว์เซอร์เอง พบน้อยกว่า OS font scale มาก และ (2) แอปมีปุ่มปรับขนาดฟอนต์ของตัวเองอยู่แล้ว จึงถือว่าให้ปรับผ่านตัวควบคุมในแอปแทน

> **สิ่งที่ต้องทำ / ติดตามต่อ:**
> 1. ✅ ตรึงขนาดฟอนต์กันการขยายระดับ OS ด้วย `text-size-adjust: 100%` บน `html, body` (`src/app/globals.css`) — เสร็จแล้ว
> 2. ⏭ (ทางเลือกอนาคต ถ้าจำเป็น) หากต้องกัน Chrome slider ด้วยจริง ๆ ต้องทำ scale-to-fit ที่คง probe ไว้จริงข้ามเฟรม (rAF) แล้ววัด boost — ซับซ้อนและกระทบ overlay/ปุ่มกด ควรประเมินความคุ้มก่อนทำ
> 3. ⏭ ย้ำในเอกสารทดสอบ: รอบ QA ให้ทดสอบทั้งกรณี "OS font ใหญ่สุด" และ "Chrome Text scaling ใหญ่สุด" แยกกัน เพราะเป็นคนละกลไก
