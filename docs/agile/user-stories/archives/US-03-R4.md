## Story

**ในฐานะ** ทีมพัฒนาและทีม QA ของโครงการ
**ฉันต้องการ** หน้ารวมเกมทุกเกมที่กดเข้าเล่นได้ทันทีโดยไม่ต้องไล่ flow ตั้งแต่หน้าแรก
**เพื่อที่จะ** ตรวจสอบเกมตาม Acceptance Criteria ได้เร็วขึ้น และไม่ทำให้ข้อมูลทดสอบปนเปื้อนข้อมูลวิจัยจริง

## บริบทของปัญหา (Why)

ปัจจุบันเกมทุกเกมเข้าถึงได้ทางเดียวคือผ่าน route `/lessons/[id]/game` ซึ่ง:

1. **มี session guard บังคับ** — ถ้ายังไม่ผ่าน consent + ระบุกลุ่มอายุ จะถูก redirect ไป `/consent` ทันที ทำให้ทุกครั้งที่จะดูเกมต้องกรอกฟอร์มใหม่
2. **เกมบางบทถูกล็อก** — ต้องเล่นบทก่อนหน้าให้จบก่อนถึงจะปลดล็อกบทถัดไปได้
3. **เขียนข้อมูลจริงทุกครั้ง** — จบเกมแล้วบันทึก progress, ยิง event เข้าตาราง `action_logs` และ redirect ไปหน้า summary ทันที ทำให้ข้อมูลรอบทดสอบปนกับข้อมูลที่ทีมวิชาการจะใช้วิเคราะห์

Sprint นี้มีงาน QA เกม G3/G5/G6 ค้างอยู่ทั้ง 3 ตัว และ deadline งานอบรมเชียงใหม่คือ 6–7 ส.ค. 2569 — เกมอย่าง G5 (ต้องดูอนิเมชั่นซ้ำหลายรอบ) และ G6 (มี 3 สถานการณ์) ยิ่งเสียเวลากับการไล่ flow มากเป็นพิเศษ

## Acceptance Criteria

- [x] มี route `/dev/games` แสดงรายการเกมทั้งหมดเป็นการ์ด กดแล้วเข้าเล่นเกมนั้นได้ทันทีในหน้าเดียวกัน
- [x] **ไม่ติด session guard** — เข้าได้โดยไม่ต้องผ่านหน้า consent
- [x] **ไม่เขียนข้อมูลจริง** — ใช้ mock `onFinish` และ mock `logEvent` เท่านั้น ห้ามยิง event เข้าตาราง `action_logs` และห้ามเขียน progress/ดาวลง localStorage หรือคุกกี้
- [x] มี **แผงแสดง event log แบบเรียลไทม์** บนหน้าจอ เพื่อให้ QA ตรวจได้ว่าเกมยิง event ครบตามที่สเปกกำหนด (ตามกติกาโครงการที่ทุก action สำคัญต้องยิง log)
- [x] เมื่อเกมจบ แสดงจำนวนดาวที่เกมส่งกลับมาผ่าน `onFinish(stars)` พร้อมปุ่ม "เล่นใหม่" และ "กลับหน้ารวมเกม" (ไม่ redirect ไปหน้า summary)
- [x] แสดงเกมที่ยังไม่ได้พัฒนา (G4, G7, G8) เป็นการ์ดสถานะ "ยังไม่พัฒนา" กดไม่ได้ เพื่อให้เห็นภาพรวมความคืบหน้าของเกมทั้งหมด
- [x] **ปิดกั้นบน production โดยค่าเริ่มต้น** — ต้องตั้ง env `ENABLE_DEV_HUB=true` (หรือ `NEXT_PUBLIC_ENABLE_DEV_HUB=true`) จึงจะเข้าได้; เช็กฝั่ง Server Component ตอน runtime เพื่อให้เปิด/ปิดจาก Portainer ได้โดยไม่ rebuild image — เพื่อไม่ให้ผู้สูงอายุหลงเข้ามาระหว่างงานอบรมจริง
- [x] หน้ารวมเกมเป็นเครื่องมือภายใน **ไม่ต้องยึดกติกา Accessibility ของผู้สูงอายุ** (ฟอนต์ ≥ 20px, no-scroll) แต่ตัวเกมที่เรนเดอร์อยู่ข้างในต้องแสดงผลเหมือนของจริงทุกประการ
