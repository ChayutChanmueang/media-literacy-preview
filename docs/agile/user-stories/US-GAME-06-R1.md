## 📖 Description

**ฉันต้องการ** ให้หน้าจอแชท LINE จำลองของ G6 เหมือนของจริงและพอดีจอทุกขนาด

## 🎯 ขอบเขตงานรื้อ (Rework Scope)

> หมายเหตุ: **กลไกหลัก v2.0 (อ่านฟองข้อความอัตโนมัติ → เลือกตอบ ยอมรับ/ปฏิเสธ/นิ่งเฉย + `isSafe`) มีในโค้ดแล้ว** — งานนี้เน้น UI/layout/fidelity ไม่ใช่รื้อกลไก

1. **UI ใหม่ (LINE fidelity)** — ทำหน้าตาให้ตรง [§3 LINE UI Fidelity Teardown](../../gdd/design-g6.md) v2.1: chat header เหลือเฉพาะโปรไฟล์กับชื่อบัญชี (ไม่มีปุ่มกลับ/โทร/เมนู), ฟองข้อความซ้าย/ขวา, พื้นหลังลายจุด — ใช้ design token กลาง + คงข้อความกำกับ *"หน้าจอจำลองเพื่อการเรียนรู้ ไม่ใช่แอป LINE จริง"*
2. **Layout ใหม่** — single-screen: กรอบแชท + **ปุ่มตอบ 1 แถว** (ดูสเปกด้านล่าง) + แผงเฉลย (ตีกรอบแดง Red Flag) + การ์ดสรุป "หยุด คิด ถาม ทำ" อยู่ในเฟรมเดียว ไม่ scroll (ระวังพื้นที่แชทยาว — ต้องออกแบบ scroll เฉพาะโซนฟองข้อความ ไม่ให้ทั้งหน้าเลื่อน) — โซนปุ่มที่บีบจาก 3 แถวเหลือ 1 แถวช่วยคืนพื้นที่ให้แชทมากขึ้น
3. **Logic บางจุด (ทบทวนกับ GDD)** — ยืนยันให้ตรง v2.0:
   - ฟองข้อความทยอยขึ้นเอง ~0.9 วิ/ฟอง + typing indicator (ไม่ใช่จับเวลากดดัน)
   - ปุ่มตอบกดได้ **เฉพาะเมื่ออ่านครบทุกฟองแล้ว**
   - "ปฏิเสธ" กับ "นิ่งเฉย" = ปลอดภัยเท่ากัน, มีเพียง "ยอมรับ" ที่เสี่ยง (ตาม `isSafe`)
   - ไม่ตอบเกิน 20 วิ → คำใบ้ชวนคิดเบาๆ (ไม่บังคับ)
   - *(รายการ logic fix ที่เจาะจงให้ groom กับทีม/GDD ตอนเริ่มงาน)*

## 🎛 สเปกปุ่มตอบ (เคาะแล้ว 2026-07-30) — G6 ต่างจาก G1/G3 อย่างมีนัยสำคัญ

> **หมายเหตุ (2026-07-30):** สเปกด้านล่างนี้ **override แนวทางเดิม "สีกลางเหมือนกันทุกปุ่ม"** ตามคำสั่งผู้ใช้

1 แถว 3 ปุ่มเท่ากัน **ชิดขอบล่างจอ**, ติดกัน, `radius 25px 25px 0 0`, ปุ่มสูง (~100px) ไอคอนบน+คำล่าง — **มีแค่ไอคอน + label (เอา sub-label เล็กในวงเล็บออก)**

- **ลำดับปุ่ม (สลับ):** **ปฏิเสธ → ยอมรับ → นิ่งเฉย** (`RESPONSE_ORDER = ['refuse','accept','ignore']` — เอา "ปฏิเสธ" ไว้ปุ่มแรก)
- **ไอคอนนิ้วโป้ง (เข้าธีม G1/G3):** ยอมรับ=👍 `ThumbsUp`, ปฏิเสธ=👎 `ThumbsDown`, นิ่งเฉย=🙈 `EyeOff`
- **สีพื้นหลังเต็มปุ่ม:** ปฏิเสธ=**แดง** (accent-error), ยอมรับ=**เขียว** (accent-success), นิ่งเฉย=**เหลือง** (amber, ตัวอักษรเข้มเพื่อ contrast)
- **label:** "ปฏิเสธ" / "ยอมรับ" / "นิ่งเฉย" (คำกริยาหลัก ไม่มีวงเล็บ)
- ⚠️⚠️ **คำเตือน (flag แล้ว ผู้ใช้ยืนยันเดินหน้า 2026-07-30):** "ยอมรับ" = ทำตามมิจฉาชีพ = คำตอบ**อันตราย** (`isSafe:false`) แต่กำหนดเป็น **เขียว + 👍** (ตาม convention ปุ่ม OK/Cancel) — เสี่ยงชวนผู้สูงอายุกดทำตามมิจ + สีคงที่ทุกข้อ = บอกใบ้คำตอบ ผู้ใช้รับทราบและเลือกใช้ (ย้าย "ปฏิเสธ" เป็นปุ่มแรกเพื่อให้เห็นทางปลอดภัยก่อน) — **ให้ทีมวิชาการ/UX ทบทวนก่อน production**
- คงกติกา: ปุ่มกดได้เฉพาะหลังอ่านฟองครบ (disabled จน conversationDone)

## 🔀 Flow ใหม่: Intro → Chat (แก้ crowding 2026-07-30)

ปัญหา: title สถานการณ์ + instruction กินที่ด้านบน จนจอจำลอง + ปุ่ม บีบจนแทบไม่เหลือที่ (จอ 16:9) → แยกเป็น 2 เฟสต่อ 1 สถานการณ์:
1. **Intro (เฟสแรก):** เต็มจอแสดง **สถานการณ์** (หัวข้อ + คำนำสั้น) — ปุ่มล่าง "อ่านข้อความเลย →" (ข้ามทันที); ถ้าไม่กด ระบบ **auto ไปหน้าแชทเองใน 30 วินาที** (จังหวะนำทาง ไม่ใช่จับเวลาตอบ/ทำโทษ — มี progress บางๆ + ปุ่มข้าม)
2. **Chat (เฟสสอง):** หน้าจำลอง LINE เต็มที่ (ไม่มี title ใหญ่บังแล้ว เพราะโชว์ในเฟส intro ไปแล้ว) เหลือแค่ instruction เล็ก; ฟองทยอยขึ้น → อ่านจบ → **ปุ่ม 3 ตัวเลือกแสดงแทนปุ่มข้าม**
- bubble reveal เริ่มเมื่อเข้าเฟส chat เท่านั้น (gate ด้วย `introDone`); reset ทุกสถานการณ์ใหม่

## 📱 จอ LINE จำลอง — Responsive สูง + Auto-scroll (2026-07-30)

จากปัญหาจริง: มือถือผู้สูงอายุสเปคต่ำมักจอ **16:9 (ไม่ยาว)** → จอจำลองเดิมสูงเกิน ดันทั้งหน้าให้ scroll ยาว
- **โซนแชท scroll ตามพื้นที่จริง (flex ไม่ใช่ vh)** — เฟส reading: กรอบจอ `flex-1` + chat body `flex-1 overflow-y-auto` → จอถูกบีบเล็กแค่ไหน แชทก็ scroll พอดีพื้นที่จริง (แก้ปัญหา `40vh` เดิมที่ไม่ตามจอจริง); เฟส reveal: chat body `max-h-[38vh]` + เลื่อนทั้งหน้าใน scroll-region
- **Auto-scroll:** ฟองใหม่ทยอยขึ้น → chat body เลื่อนลงล่างสุดอัตโนมัติ (ref + `useEffect` on `revealedCount`)
- **ตัด status bar (เวลา/wifi/แบต) + input bar (พิมพ์ข้อความ) ออก** — คนแก่จะงงคิดว่าส่งข้อความได้จริง; จอจำลองเหลือแค่ **header (ใครคุย) + ฟองข้อความ**
- **คำกำกับ "ไม่ใช่แอป LINE จริง"** ย้ายเป็นแถบเล็ก (11px) **ในกรอบจอด้านล่าง** (แทนตำแหน่ง input bar เดิม — policy ต้องมี)
- **instruction "อ่านข้อความข้างบน...ตอบกลับยังไง"** ย้ายไปแสดง**เป็นข้อความระบบในแชท** (self-center, กรอบขอบมน `--radius-xl`, ตัวหนา 20px, คล้ายข้อความตอน block คน) โผล่เมื่ออ่านครบทุกฟอง — ไม่มี `<p>` ใต้กรอบแล้ว
- **ลบกล่อง hint "ลองอ่านข้อความอีกครั้ง..." + logic idle-hint ทั้งหมด** (state/effect/constant/event) เพราะความหมายซ้ำกับข้อความระบบในแชท
