## 📖 Description

**ในฐานะ** ผู้เล่นที่เก็บคะแนนครั้งแรก
**ฉันต้องการ** รู้ทันทีตอนกรอกชื่อว่าชื่อนี้มีคนอื่นใช้แล้วหรือยัง
**เพื่อที่จะ** แยกตัวเองออกจากผู้เล่นคนอื่นบนกระดานคะแนนได้ชัดเจน

> เงื่อนไข: ไม่เพิ่มสคริปต์/การดึงข้อมูลแยกต่างหากฝั่ง client — ตรวจในคำขอส่งคะแนนที่มีอยู่แล้ว

---

## 🔎 สถานะปัจจุบัน (2026-11-13)

- ผู้เล่น = `player_uuid` + ชื่อ เก็บใน `localStorage` (`naplab_ml_leaderboard_player`, [leaderboardPlayerService.ts](../../../src/services/leaderboardPlayerService.ts)) — ตอนสร้างโปรไฟล์ไม่ติดต่อ server
- ไม่มีตารางรายชื่อผู้เล่นกลาง: ชื่อถูกคัดลอกลงทุกแถวคะแนนใน `player_info` ([supabase-schema.sql](../../supabase-schema.sql)) และไม่มี constraint กันชื่อซ้ำข้าม `player_uuid`
- server รู้จักชื่อครั้งแรกตอน `POST /api/game-results` ([route.ts](../../../src/app/api/game-results/route.ts))
- ผู้เล่นที่มีโปรไฟล์ในเครื่องแล้ว ข้าม popup กรอกชื่อไปกระดานคะแนนเลย — popup กรอกชื่อขึ้นเฉพาะตอนยังไม่มีโปรไฟล์ (ครั้งแรก / ล้างข้อมูลเบราว์เซอร์)

## 🛠️ ทางเลือกที่เสนอ

### A — ตรวจในคำขอส่งคะแนนเดิม (แก้น้อยสุด)
- ใน `POST /api/game-results` ก่อน `INSERT`:
  ```sql
  SELECT 1 FROM player_info
  WHERE lower(trim(name)) = lower(trim($1)) AND player_uuid <> $2
  LIMIT 1
  ```
  เจอ → ตอบ `409 { error: "ชื่อนี้มีผู้ใช้แล้ว" }` ไม่บันทึก · ผู้เล่นเดิมผ่านเพราะ `player_uuid` ตัวเองถูกยกเว้น
- **ต้องปรับ flow:** ตอนนี้ "ยืนยัน" ใน `NameEntryPopup` เก็บชื่อแล้วปิดทันที คะแนนส่งทีหลังโดย `LeaderboardPopup` → ผู้เล่นใหม่ต้องให้ popup กรอกชื่อส่งคะแนนเองและรอผล (409 = แสดง error ใต้ช่องชื่อ, สำเร็จ = เปิดกระดาน) และเขียนโปรไฟล์ลง `localStorage` หลังสำเร็จเท่านั้น
- ข้อเสีย: มี race (สองคนส่งชื่อใหม่เดียวกันพร้อมกันผ่านได้ทั้งคู่); ควรเพิ่ม index บน `lower(trim(name))` เพื่อไม่ให้ scan ทั้งตาราง

### B — ตาราง `players` (ถูกต้องที่สุด)
- `players (player_uuid PK, name UNIQUE)` — server insert แถวผู้เล่นใน transaction เดียวกับคะแนนแรก ให้ DB บังคับ uniqueness เอง ไม่มี race
- ต้อง migration ทั้งสองฐานข้อมูล + backfill ชื่อเดิม (ซึ่งอาจซ้ำกันอยู่แล้ว ต้องตัดสินใจว่าจะจัดการอย่างไร)

## ❓ ประเด็นที่ต้องตัดสินใจกับ backend dev

1. ควรบังคับชื่อไม่ซ้ำจริงไหม — กลุ่มผู้ใช้เป็นผู้สูงอายุ ชื่อยอดนิยม (เช่น "สมชาย") จะชนบ่อย การบังคับคิดชื่อใหม่เพิ่มแรงเสียดทาน; ปัจจุบันกระดานแยกผู้เล่นด้วย `player_uuid` และไฮไลต์แถวตัวเองอยู่แล้ว (ทางเลือกอ่อน: ยอมชื่อซ้ำ ไม่ทำอะไรเพิ่ม)
2. กติกาเทียบชื่อ: ไม่สนตัวพิมพ์/ช่องว่าง? ซ้ำข้ามทุกเกม หรือเฉพาะเกมเดียวกัน?
3. ทางเลือก A หรือ B
4. โหมดกระดานในเครื่อง (localhost / เกม `localOnly`, [localLeaderboardService.ts](../../../src/services/localLeaderboardService.ts)) ไม่ส่งคะแนนเข้า server — ตรวจในเครื่อง หรือไม่ตรวจเลย
5. การตรวจชื่อซ้ำเปิดช่องให้ลองเดาว่าชื่อใดเคยถูกใช้ (ความเสี่ยงต่ำ แต่ควรรับรู้)

## ✅ Acceptance Criteria (ร่าง — ใช้เมื่อตัดสินใจทำ)

- [ ] ผู้เล่นเดิม (มีโปรไฟล์ในเครื่อง) เก็บคะแนนได้ตามปกติ ไม่ถูกตรวจชื่อชนกับตัวเอง
- [ ] ไม่มีการดึงรายชื่อผู้เล่นลงฝั่ง client
